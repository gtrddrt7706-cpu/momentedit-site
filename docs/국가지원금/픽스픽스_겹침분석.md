# 픽스픽스 겹침 분석 — 우리 자산을 두 칸으로 가른다

> 2026-09-07 · 코워크 「요청 02」 §4 첫 항목에 대한 답
> 기준: 우리 자산 = `02_자산팩트시트.md`(코드 실측) · 픽스픽스 기능 = 코워크 실측(pixpics.io/studio·/pricing)
> ★내 환경에서 pixpics.io 는 egress 차단이라 **원문 대조를 못 했다**. 아래 픽스픽스 열은 코워크 실측을 그대로 옮긴 것이다.
>  다만 검색으로 독립 확인된 것이 하나 있다 — 픽스픽스는 자사를 **Pixieset·Pic-Time·ShootProof 의 한국판**
>  (완전 한국어·원화·카톡 알림·네이버페이)으로 소개한다. 셋 다 **사진 전달(client gallery)** 제품이다.
>  즉 픽스픽스의 무게중심은 «촬영 상품»이라는 코워크의 판단은 제3의 근거로도 지지된다.

## A. 겹치는 것 — 신청서에서 뺀다

이 칸에 있는 것을 앞세우면 «픽스픽스 월 8,000원이면 되잖아요» 한 줄로 끝난다.

| 우리 자산 | 픽스픽스 | 판정 |
|---|---|---|
| 상담 예약·슬롯·캘린더 연동·더블부킹 방지 | 예약 접수 + 구글/네이버/애플 캘린더 동기화 + 중복예약 방지 | **완전 겹침** |
| 고객 DB·여정 단계 관리 | 고객 DB·고객별 예약 페이지 | **완전 겹침** |
| 전자계약(요청→발송→서명→보관) | 견적·설문·**계약서**·청구서 링크 통합 | **겹침** (깊이는 우리가 위: 손서명 canvas·동의기록 JSON·약관지문·72h 자동파기) |
| 결제 마일스톤(계약금·중도금·잔금)·리마인드 | 카드/네이버페이/카카오페이·무통장·**분할결제**·자동 결제 리마인더 | **겹침** (그쪽이 위: 우리 카드결제는 아직 비활성) |
| 카카오 알림톡 발송 | 카카오톡 알림톡 발송 | **완전 겹침** |
| 결과물 전달(원본→선택→보정→컨펌→전달) | 클라이언트 갤러리 + **AI 원본 선별** | **겹침** (그쪽이 위) |
| 관리자 권한·계정 | 팀원 권한 관리(Pro 2명·Premium 4명) | **완전 겹침** |
| — | iOS/Android 네이티브 앱 | **그쪽만 있음** |

→ **결론: 「예약·계약·결제·알림·사진전달」 축은 우리 차별점이 아니다.** 이 다섯 단어를 신청서 앞면에서 지운다.

## B. 겹치지 않는 것 — 여기만 남긴다

픽스픽스의 여정은 `예약 → 계약 → 결제 → 촬영 → 사진 전달 → 끝` 이다. 아래는 그 뒤이거나 바깥이다.

| 우리 자산 | 실측 근거 | 픽스픽스 |
|---|---|---|
| **모바일 청첩장 24종** (라이브 16 + 갤러리 8) · 랜덤 토큰 열람 보호 · 소셜봇 전용 OG 주입 | `i/`·`i-family/` 37,036줄 | 없음 |
| **식순 빌더** — 5개 코스 프리셋·19+ 순간·시간예산 자동계산·순간별 나레이션 오디오 | `order-preview.html` + `ritual-advisor` | 없음 |
| **좌석 배치 캔버스** — 삼각함수 원형테이블 자동배치·자리별 음료 집계·입석 초과요금 | `mypage.html` | 없음 |
| **하객 좌석 조회** — 이름 검색·**프라이버시 기본값 '내 자리만'**(서버가 본인 테이블만 응답) | `seat.html` | 없음 |
| **하객 안내 허브** — 좌석·식사·다이닝·사진모으기 한 링크 · **하객 노출 시 가격정보 자동 필터** | `guide.html` | 없음 |
| **하객 편지** — 신랑신부에게만 전달 · 금칙어 변형·띄어쓰기 회피 탐지 | GAS | 없음 |
| **디지털 참석** — Vimeo 비공개 1080p를 자체 UI로 감싸 광고·목록노출·접속자수 제거 · 무인 자동 부착 폴링 | `live.html` | 없음 |
| **어른 안내** — 글자 4단계·음성 낭독(TTS)·A4 인쇄 최적화 | `parents.html` | 없음 |
| **다이닝 파트너 검증** — 카카오맵 전수 대조·월간 자동 폐업/상호변경 탐지 | `88_place_audit.gs` | 없음 |
| **환불·변경 견적 엔진** — 계약 조항을 코드로 | GAS | 없음 |

→ **결론: 안 겹치는 열 개는 전부 «예식 당일과 그 하객»이다.** 촬영이 아니다.

## C. 그런데 B칸에는 치명적인 조건이 붙어 있다 (내가 찾은 것)

B칸 열 개는 **전부 모먼트에디트 상품 사양에 결합돼 있다.**

- 식순 빌더의 5개 코스 프리셋 = **140분 시그니처 시퀀스** 그 자체
- 좌석 캔버스 = **양가 직계 25명·원형 테이블** 전제
- 안내 허브 = **다이닝 파트너사에 직접 지불**하는 우리 결제 구조 전제
- 어른 안내 = 우리 브랜드 톤·우리 상품 설명
- 다이닝 검증 = **우리 스튜디오 반경 7km** 하드코딩

즉 «남의 예식에 그대로 팔 수 있는가»의 답은 지금은 **아니오**다. 파라미터화가 필요하고,
그건 «이미 만들었다»가 아니라 «다시 만든다»다. 이 사실을 모르고 A'를 내면
1R 서면이 아니라 **2R 대면에서** 깨진다 — 더 나쁘다.

---

## D. 그러면 21만 줄은 어디서 값을 하는가

A칸에서도 B칸에서도 «남에게 파는 물건»으로는 약하다. 그런데 한 자리에서는 무적이다.

> **«부부 2인이 웨딩 스튜디오를 어떻게 혼자 굴리는가»의 답.**

이때는 픽스픽스와 비교당하지 않는다. 비교 대상이 «다른 예비창업자»이기 때문이다.
그리고 이 프레임에서는 A칸(예약·계약·결제)도 자산으로 되돌아온다 — 팔 물건이 아니라
**내가 이미 갖춘 운영 체력**이므로.
