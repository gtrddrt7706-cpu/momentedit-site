## 대기 루프를 만들지 않는다 [STALE_WAIT] (2026-09-20 사장님 지시 *"항상 이런거 없는지 탐지 자동으로해 토큰갈아먹잖아"*)

백그라운드에 대기 작업 **5개**가 떠 있었고 그중 **4개가 찌꺼기**였다. 제일 오래된 것이 **1시간 27분**째였다.
사장님이 화면을 캡처해 보여 주기 전까지 나는 「하나만 돈다」고 답하고 있었다.

### 왜 생겼나 — 한 가지 원인이다

```
until ! pgrep -f "merge-guard.sh" >/dev/null 2>&1; do sleep 10; done
```

이렇게 걸면 **그 패턴이 자기 자신의 명령줄에도 걸린다.** pgrep 은 자기 프로세스만 빼고 보는데,
이 루프를 돌리는 «부모 bash» 의 명령줄에 그 문자열이 통째로 들어 있다.
그래서 조건이 **수학적으로 풀릴 수 없고**, 알림만 계속 올라와 토큰을 먹는다.

★더 나쁜 것 — 그중 하나는 조건이 풀리는 순간 `merge-guard` 를 **또 한 번** 돌려
  결과 파일을 덮어쓸 참이었다. 지금 도는 점검과 브라우저를 놓고 경합했을 것이다.

### 쓰지 말 것 / 쓸 것

| 안 됨 | 됨 |
|---|---|
| `until ! pgrep -f "<내 명령줄에 있는 문자열>"` | **백그라운드 작업 알림을 그냥 기다린다** — 하니스가 끝날 때 알려 준다 |
| 같은 대상에 타이머 여러 개 | `run_in_background` 로 «일 자체»를 던지고 결과만 읽는다 |
| 폴링으로 완료 확인 | 완료 표식 파일(`touch done`)을 두고 `[ -f done ]` 으로 본다 |

- **한 대상에 대기 타이머는 하나만** (2026-08-15 규칙과 같다). 이미 걸어 둔 게 있으면 그것을 기다린다.
- 꼭 폴링해야 하면 패턴에 **자기 명령줄에 없는 문자열**을 쓴다(파일 경로·PID 등).
- 결과 파일에는 **커밋 해시를 박는다**(`gate-<sha>.txt`) — 11일 전 파일을 읽고
  「ALL MARKERS OK」라고 보고한 사고가 같은 날 있었다.

### 탐지 (자동)

`scripts/audit/stale-waiters.sh` — 대기 루프의 pgrep 패턴을 꺼내 **그 프로세스 자신의 명령줄에
맞는지** 본다. 맞으면 «느린 것»이 아니라 «안 끝나는 것»이라 **오탐이 없다.**
- `.claude/settings.json` 의 **Stop 훅**으로 매 턴 끝에 자동 실행된다. 찌꺼기가 있을 때만 말한다.
- 깨 보고 믿었다 — 똑같은 자기참조 루프를 띄우니 pid 까지 찍어 잡았고(종료코드 1), 죽이니 0 이 됐다.
