## 0. 목적 한 줄

관리자 상세의 **강제 단계 변경 드롭다운에서 '후기'를 골라** 고객을 후기(설문) 화면으로 보낼 수 있게 한다.

지금은 그 상태로 보내는 유일한 경로가 `결과물 전달 완료` 처리(원본 링크 필수 · 미수금 가드)뿐이라, 후기를 다시 받고 싶거나 잘못 넘긴 건을 되돌릴 때 쓸 레버가 없다.

---

## 1. 현황 — '후기'는 이미 준(準)단계다

조사 결과 후기는 **이미 단계처럼 동작하되, `현재단계` 값이 아닌 두 조각으로 구현**돼 있다.

| 조각 | 위치 | 역할 |
|---|---|---|
| `설문상태` 컬럼 (`대기`/`완료`/`건너뜀`) | `00_platform-config.gs:123` | 후기 진행 여부의 실제 저장소 |
| 마이페이지 합성 스텝 | `mypage.html:1959-1972` | `list.concat(['후기'])` — 백엔드에 없는 10번째 스텝을 클라이언트가 덧붙임 |

그래서 **고객 화면에는 후기 스텝과 '여정 완료'가 이미 보이고**, 관리자 드롭다운·파이프라인에만 없다. 아카이브 판정도 `단계=결과물전달 AND 설문상태∈{완료,건너뜀}`이라는 **이중 조건**으로 돌아간다(`admin.gs:1066-1074`).

핵심 포인트: 이건 "새 개념을 만드는 일"이 아니라 **흩어진 후기 상태를 단계 체계로 승격시키는 일**이다.

---

## 2. 설계 — 후기 = "후기 받는 중" 상태

사용자 지시("그쪽으로 강제이동")에 맞춰 **후기 = 마이페이지 설문 카드가 떠 있는 대기 상태**로 정의한다.

### 2-1. 단계 흐름

```
… → 예식완료 → 결과물전달 → 후기 → (아카이브)
                  ↑ 전달 처리       ↑ 후기 대기        ↑ 설문 마감(완료/건너뜀)
```

- `결과물전달` — 전달 처리 직후. 결과물 확인·선택·컨펌이 도는 구간.
- `후기` — 설문 카드를 띄우고 답을 기다리는 구간. **관리자가 강제이동으로 직접 보낼 수 있는 지점.**
- 아카이브 — 단계는 `후기`에 머문 채 `설문상태`가 마감되면 종료 처리.

### 2-2. 아카이브 판정 (★결정 필요 1)

| 안 | 판정식 | 장점 | 단점 |
|---|---|---|---|
| **가 (추천)** | `단계=후기 AND 설문상태∈{완료,건너뜀}` | 현행 이중 조건의 형태를 그대로 유지 → 회귀 위험 최소 | 여전히 두 값을 함께 봐야 함 |
| 나 | 단계 `완료`를 하나 더 추가해 `단계=완료` 단독 판정 | 판정이 한 값으로 깔끔 | 11단계로 늘고 수정 지점이 크게 증가 |

**추천: 가.** 이번 작업의 목적은 강제이동 레버지 아카이브 리팩터가 아니다. 나는 별건으로 분리한다.

### 2-3. 전이 규칙

| 계기 | 전이 | 비고 |
|---|---|---|
| `adminMarkDelivered` | → `결과물전달` | **현행 유지**(변경 없음) |
| 고객 후기 제출 (`handleSubmitSurvey`) | 단계 이동 없음, `설문상태='완료'` | 단계는 `후기`에 머묾 |
| 관리자 `후기 넘기기` (`adminSkipSurvey`) | 단계 이동 없음, `설문상태='건너뜀'` | 상동 |
| **관리자 강제이동 → `후기`** | `결과물전달` → `후기` | **이번에 새로 여는 경로.** `설문상태`를 `대기`로 되돌려 고객 화면에 설문 카드 재노출 |
| 강제이동 → `결과물전달`(되돌리기) | `후기` → `결과물전달` | `_clearForwardData`가 설문 데이터 삭제 |

`결과물전달 → 후기` 자동 전이는 **이번 범위에서 제외**한다(★결정 필요 2). 자동으로 넘기면 지금의 "결과물전달 = 후기 대기" 운영 감각이 바뀌고 큐·보드 문구를 전부 다시 맞춰야 한다. 강제이동 레버만 먼저 열고, 운영해보며 자동화 여부를 판단한다.

## 4. 반영 순서 (배치)

리스크 낮은 순으로 쪼개고, 각 배치마다 merge-guard + 렌더 검증을 돌린다.

**배치 1 — 백엔드 단계 승격 (GAS · 재배포 1회)**
1 → 2 → 3 → 4 → 22 → 13 → 24
목적: 값이 저장·조회되고 결과물 카드가 살아 있는 상태까지. 이 시점에는 아직 관리자 UI에 안 보임.

**배치 2 — 관리자 (GAS + admin.html)**
5 → 6 → 7 → 8 → 9 → 10 → 11 → 12 → 14 → 15 → 16 → 17
목적: 드롭다운·큐·보드·아카이브·롤백이 새 단계를 일관되게 다룸. **사용자 지시의 본체(12번)가 여기.**

**배치 3 — 고객 화면 (mypage.html · 프론트 배포)**
18 → 19 → 20 → 21
목적: 합성 스텝 제거 후에도 STEP N/10과 '여정 완료'가 그대로 보이게.

★배치 3을 배치 1·2보다 먼저 반영하면 **후기 스텝이 사라진 화면**이 배포된다. 순서 역전 금지.

---

### 4-1. 구현 메모 — #18은 '제거'가 아니라 '조건부 폴백'(2차)

기획은 합성 스텝 `list.concat(['후기'])`의 **제거**를 지시했다. 그대로 지우면 목적(중복 방지)은 달성되지만,
**GAS 재배포 전까지 구 서버가 `stageList`에 후기를 담아주지 않아 후기 스텝이 통째로 사라지는 공백**이 생긴다.
프론트(Vercel)는 병합 즉시 배포되고 GAS 재배포는 수동이라, 같은 PR에서는 배치3이 배치1·2보다 먼저 라이브에 닿는다.

그래서 **`if (list.indexOf('후기') === -1) list = list.concat(['후기']);`** 로 반영했다.
- 새 서버(후기 포함) → 합성하지 않음 → 중복·STEP 부풀음 0 (기획 목적 달성)
- 구 서버(후기 없음) → 폴백으로 붙임 → 재배포 전에도 화면이 깨지지 않음

merge-guard 음수 가드는 **무조건 재삽입만** 잡는다(조건부 폴백은 허용).

## 5. 리스크와 회귀 검증

| 리스크 | 감지 방법 |
|---|---|
| `RESULT_STAGES` 누락 → 결과물·설문 카드 소멸 | 후기 단계 고객으로 마이페이지 렌더 → 결과물 카드·설문 카드 존재 확인 |
| 마이페이지 스텝 중복(후기 2회) | 진행바 스텝 수 = 10 (시그) / 7 (스냅) 확인, 라벨 중복 0 |
| 아카이브 미진입 → 큐에 영구 잔류 | 후기 제출·넘기기 후 `adminHome` 큐에서 사라지는지, 아카이브 목록에 뜨는지 |
| 롤백이 설문을 안 지움 | 후기 → 결과물전달 강제이동 후 `설문상태`·`설문응답` 비었는지 |
| 강제이동해도 설문 안 뜸 | 결과물전달 → 후기 강제이동 후 고객 화면에 설문 카드 노출 확인 |
| 구 데이터(단계=결과물전달, 설문완료) 취급 | 기존 아카이브 고객이 그대로 아카이브에 남는지 |

merge-guard에 신규 마커 등록: `STAGE_REVIEW`(단계 승격), `RESULT_STAGES 후기 포함`, `mypage 합성 스텝 제거` 음수 가드.
