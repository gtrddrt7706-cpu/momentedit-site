# PLAN · 식순 빌더 기획 (마이페이지 · 나레이션 예식)

> 2026-07-05 사용자와 대화로 확정. 마이페이지 '예식 준비 > 식순' 트랙 전면 개편 기획.
> 핵심: 사회자·주례 없는 **AI 성우 나레이션 진행**이 모먼트에디트의 예식 포맷.
> 고객은 "이미 완성된 뼈대"에 원하는 순간만 얹고, 시스템이 나레이션 대본·큐시트를 자동 완성한다.

## 0. 확정된 원칙 (결정 로그)

| 결정 | 내용 |
|---|---|
| ✅ 진행 포맷 | **AI 성우 나레이션이 기본·추천.** 주례 완전 삭제(편지·덕담이 대체). 지인은 축사·퀴즈 진행 등 "순서 담당자"로 참여 |
| ⏳ 사회자 예외 경로 | Step 1에 작은 링크로 "지인 사회자 진행" 전환 허용. **같은 빌더·같은 데이터, 출력만 전환**(나레이션 오디오 ↔ 사회자 대본). 섭외 대행 없음(직접 섭외+대본 제공). 하이브리드는 상담 조정. GO 콘솔은 BGM·영상만 담당 |
| ✅ 입장 | **신랑·신부 동시 입장 고정** (방식 선택 없음) |
| ✅ 퇴장 | **없음.** 식 종료 후 그 자리에서 가족·지인 단체촬영으로 연결 (140분 시퀀스 구조) |
| ✅ 환영 인사 | 고정 (두 분 직접 / 나레이션에 맡기기 택1) |
| ✅ 기본값 철학 | 선택 이벤트 전부 기본 OFF. "하나도 더하지 않아도 완성된 예식" 명시. 담백함이 기본, 전통 요소는 얹는 것 |
| ✅ 게이트 | 분위기 톤 1문항만 (차분·감동 / 밝고 유쾌 / 담백·심플) — 추천 정렬·뱃지만 바꾸고 숨기지 않음 |
| ⏳ 제안 유지 | 서약 고정(문답/자작 택1) · 예물 교환 고정(옵트아웃 허용) · 폐식 멘트 1분 고정 |
| ⏳ 제안 유지 | 끝 신호 = "마지막 문장" 한 줄 입력 · BGM 톤 큐레이션 + 지정곡 3포인트 · 당일 GO 콘솔 |

### 시간 구조 (본예식 30분 = 입장 5분 + 본식 25분, sequence-modal.js 근거)

```
🔒 고정            10분   개식 2 + 동시입장 5 + 성혼선언 2 + 폐식·촬영안내 1
🔒✏️ 고정(형태선택)  7~8분   환영 2 + 서약 3~4 + 예물교환 2
🎨 자유 예산        12~13분  선택 이벤트 3~4개 (나레이션 전환 시간 포함 계산)
```

- 초과 시: 경고만(저장 차단 없음) + "상담 때 함께 조정해요"
- 순서 규칙: 자유 구간 마지막이 유쾌 이벤트면 "마지막은 차분한 순서 추천" 소프트 안내 (연구 리포트: 단체촬영 진입 동선)

## 2. 이벤트 블록 3조각 모델 (운영 핵심)

```
[시작 큐]  진입 나레이션 (템플릿 자동·고객 수정 불가·미리보기 제공)
[본 내용]  사람의 시간 (길이 예측 불가)
[끝 신호]  말 이벤트 → 고객이 "마지막 문장" 한 줄 입력 → 당일 GO 타이밍 힌트
          비언어 이벤트(커팅 등) → 눈에 보이는 끝, 입력 없음
```

- 대본 자유 수정 금지. 템플릿+변수(이름·곡명 등)+요청 메모만
- 편지·서약 내용은 받지 않음: "내용은 당일까지 비밀로, 마지막 문장만 살짝" (배려 프레임)
- BGM: 톤 큐레이션 기본 + 지정곡 3포인트(입장곡 / 편지·서약 배경 / 마무리). 기존 입장·퇴장 음악 칸 대체

## 3. 당일 운영 = 원버튼 GO 콘솔 (Phase 3)

- 풀오토(타이머) 기각: 이벤트 길이 가변(±1~2분)이라 위험. 자유 조작 기각: 실수 여지
- QLab 방식 큐 스택: **GO(수동·사람 판단 순간만) / AUTO-FOLLOW(오디오 끝+n초) / MEDIA-END(영상 끝)**
- 안정장치: 전체 프리로드(오프라인 무관)·리허설 모드(파일·볼륨 점검)·나레이션 더킹 자동·전체 페이드 비상버튼·이전 다시·GO 연타 가드·화면 꺼짐 방지
- 예식당 사람 GO 약 10회. 음성인식 자동 GO는 기각(오인식 리스크 > 버튼 1회 비용)
- 파이프라인: 식순 확정 → 대본 자동 생성 → 음성 생성(v1 복사·붙여넣기, v2 API 자동) → 큐 스택 컴파일 → 전날 리허설 → 당일 GO

## 4. 마이페이지 적용 설계

### 그대로 재사용 (검증된 것)

- **TRKFLOW 위저드 프레임** (`trkShell`·`bindTrk`·`saveTrkDraft`·`_step` 이어하기) — 스텝 수만 3→동적 6
- **GAS 무변경**: `handleSaveProductionTrack`(80_production.gs)은 ritual draft를 JSON 통째 저장(검증 없음) → **Phase 1은 mypage.html만으로 완성, GAS 재배포 불필요**
- **base 데이터**: `groomKo/brideKo/weddingDate/weddingTime(본예식 시각)` 서버가 이미 채움 → 나레이션 이름 치환·실시각 큐시트 즉시 가능
- 칩·옵션 CSS(`.trk-chips`·`.inv-opt`) 재사용, 대시보드 트랙 행 구조 유지

### 스텝 구성 (동적 — 미니멀 고객은 3스텝 체감)

| Step | 내용 | 스킵 조건 |
|---|---|---|
| 1 | 나레이션 형식 소개 + 분위기 톤 택1 | — |
| 2 | 뼈대 타임라인 확인 + 서약 형태 + 환영 방식 (+예물 옵트아웃) | — |
| 3 | 더하기: 칩(시간 표기·나레이션 미리보기 펼침) + 예산 바 + "안 더해도 괜찮아요" | — |
| 4 | 순서 배치: 고정 🔒 사이 ▲▼ 이동 + 실시각 자동 표기 | 선택 0개면 스킵 |
| 5 | 디테일: 선택 이벤트당 블록 카드 1장(변수·마지막 문장·BGM) + 지정곡 3포인트 | 선택 0개면 최소화(음악만) |
| 6 | 완성: 3열 큐시트(시각/장면/오디오·나레이션 전문) 미리보기 + 저장 | — |

### 데이터 (ritualDraft v2)

```js
{ _v:2, _step:0,
  tone:'차분'|'유쾌'|'심플',
  vow:'자작'|'문답', welcome:'직접'|'나레이션', ringExchange:true,
  events:['letter','veildown',...],            // 카탈로그 key
  order:[...],                                  // 자유 구간 배치 순서
  details:{ letter:{dir,reader,after,lastLine,bgm}, song:{title,artist,who,acc,lastCue}, video:{kind,len,link}, ... },
  music:{ entry:'', peak:'', closing:'' },      // 지정곡 3포인트
  note:'' }
```

- **v1 마이그레이션** (기존 진행중·완료 고객): `mc`→버림(포맷 변경 안내 1회) · `events[구 라벨]`→새 key 매핑 · `entryMusic`→`music.entry` · `exitMusic`→`music.closing` · `songTitle/Artist`→`details.song` · `timeline/extraOrder`→`note`
- 카탈로그는 mypage.html 내 `RITUAL_CATALOG` 상수(이벤트·분·카테고리·나레이션 템플릿·디테일 스키마·뱃지)

### 완료 후

- 대시보드 행: `식순 ✓ · 7순서 · 26분 · 나레이션 대본 완성` 요약
