## 1. ① 적대적 검증 — 게이트가 초록인 채 제품이 깨진 사례 넷

## 3. ③ 모의 세계 현실성 — 어긋난 곳 둘

`scripts/audit/_gasworld.mjs` 와 진짜 `writeCell`(`automation/form-to-couple.gs:375`)을 대조했다.

### 3-1. ★모의 세계에는 「헤더가 없는 컬럼」이 존재할 수 없다

```js
// 진짜 writeCell
var c = colOf[header];
if (!c) { Logger.log('  (헤더 없음, 건너뜀: ' + header + ')'); return; }   // ← 조용히 사라진다
```

모의 세계의 `HEADERS` 는 `CUSTOMER_HEADERS + _prodCols() + 확장목록` 으로 조립된다 —
**항상 모든 컬럼이 있는 세계**다. 그래서 이 저장소가 문서로 못 박아 둔 그 사고
(`addProdTrackColumns` 주석: *"컬럼이 없는 상태로 배포되면 writeCell 이 조용히 건너뛰어
저장이 통째로 사라진다 · 화면엔 저장됐어요"*)를 **구조적으로 재현할 수 없다.**

가장 무서운 실패 모드가 모의 세계에서는 일어날 수 없는 일이다.

### 3-2. 빈 값 스킵(`force`) 규칙이 없다

진짜 `writeCell` 은 `value === '' && !force` 면 **안 쓴다**(점진 입력 보존).
모의 세계의 `setValue` 는 무엇이든 그대로 쓴다.
→ 「지우려고 빈 값을 보냈는데 안 지워지는」 부류를 모의 세계에서는 못 잡는다.

★3-1이 곧 §1-C 가 통과한 이유이기도 하다 — 컬럼이 사라지는 세계가 없으니
컬럼이 사라져서 나는 사고도 시험되지 않는다.

**메우는 방향(합의 후)**: 모의 `sheetC.getRange` 를 진짜 `writeCell` 규칙에 맞춘다 —
`COL_OF` 에 없는 헤더면 쓰지 않고 이벤트만 남기고, 빈 값은 `force` 없이는 무시.
그러면 「컬럼 없이 배포」와 「빈 값 삭제」 두 부류가 그 순간부터 시험 대상이 된다.

| `김희준 이미쿠 본식3 0123.jpg` | 100 | **109** | **9** |

부풀어 오르는 폭은 **서로 다른 앞자락의 개수**만큼이다(같은 조각은 중복 제거로 뭉쳐진다).

**왜 나쁜가 — 돈이 걸린다.**
`선택수` 는 추가 보정 견적의 **기본값**을 만든다(`over = 선택수 − 포함컷` · `RESULT.추가보정단가 = 20,000원`).
100장을 골랐는데 109로 세면 초과가 90 → 99가 되고, 화면에 *"추가 9컷을 기본으로 넣어뒀어요"* 가
**180,000원어치 더** 붙는다. 고객이 고칠 수는 있지만(*"바꾸셔도 돼요"*) **기본값이 위로 틀린다.**
게다가 `선택사진` 에 **ID 없는 조각**(`DSC` · `김희준`)이 고른 컷인 양 남아, 보정 담당이 못 찾는 항목이 생긴다.

**도달성** — 웨딩 원본 파일명에 공백은 흔하다(라이트룸·아이폰 내보내기, 신랑신부 이름 포함 규칙).
파일이 유실되지는 않는다(ID 는 살아 있다). 틀리는 것은 **수와 돈과 이름**이다.

★고치지 않았다(합의 전 메움 금지). 방향: `_gnm` 의 치환을 `[(),]` → **구분자 전체**
(`[(),\s·，、;]`)로 넓히면 한 항목이 한 토큰임이 보장된다 — 서버가 다시 쪼개는 그 정규식과 **같은 문자 집합**을
쓰는 것이 요점이다. 지금은 두 곳이 다른 집합을 보고 있어서 갈렸다.
