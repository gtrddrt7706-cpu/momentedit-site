# 예식 대본 전면 개정 — 기획

> 2026-08-14 사용자 지시: *"대본 부분 크게 기획을 해보자"* · *"코워드랑 소통하면서 최종으로 좁혀가자"*
> 두 코워크 세션이 **각자 독립으로 쓰고, 교차 비평하고, 좁혀서 확정**한다.
> 확정 전까지 **코드는 한 줄도 안 고친다.** 문서만 오간다.

---

## 1. 왜 지금 하나

지금 예식에서 나가는 말은 **한 자리에 한 문장씩**이다. 고객이 고를 수 있는 것은
'무엇을 하는가'(연출 갈래)뿐이고, '어떻게 말하는가'는 전부 우리가 정해 둔 한 벌이다.

그래서 세 가지가 생긴다.

1. **같은 예식이 나온다.** 코스를 달리 골라도 들리는 말투가 같다.
   어른 하객만 모인 자리와 친구들만 모인 자리에 같은 문장이 나간다.
2. **고객이 쓰는 예시가 형식적이다.** 서약 예시가 큰 말(영원·평생·행복)로만 되어 있어,
   보고 나서 자기 문장을 못 쓴다. 예시가 오히려 벽이 된다.
3. **더빙 비용이 이유가 안 된다.** 사용자 판단: *"더빙은 쉬우니깐"* — 문안이 늘어나는 비용은
   더 이상 이 결정을 막는 근거가 아니다.

## 2. 무엇을 정하나

### 2-A. 문안이 붙는 자리 전수 (실측 2026-08-14)

| 자리 | 지금 갈래 | 결(톤) 후보 필요 |
|---|---|---|
| 식전 안내(하객 맞이) | 4클립 | △ 검토 |
| 입장 | 6갈래(A~F) | 갈래 안에서 |
| 첫인사 | 1 | **완료** (NARV) |
| 혼인 서약 | 1 | **완료** (NARV) |
| 반지 교환 | 1 | **완료** (NARV) |
| 부모님 덕담 | 1 | **완료** (NARV) |
| 성혼 선언 | 2갈래 × 낭독자 4 | 갈래 안에서 |
| 편지 낭독 | 3갈래 | 갈래 안에서 |
| 부모님 헌정 | 3갈래 | 갈래 안에서 |
| 축배·케이크 | 3갈래 | 갈래 안에서 |
| 자유 한 칸 | 1 | **완료** (NARV) |
| 폐식·단체촬영 | 1 | **완료** (NARV) |

**★갈래를 새로 만들지 않는다.** 연출 갈래(무엇을 하는가)는 그대로 두고,
그 **갈래 안에서** 결 3벌을 낸다. 갈래 × 결을 곱해 새 축을 만들면 고르는 일이 일이 된다.

### 2-B. 결은 셋으로 고정

| 결 | 성격 | 맞는 자리 |
|---|---|---|
| **담백** | 군더더기 없이 할 일만 | 어른 하객이 많거나 짧은 코스 |
| **서정** | 그 순간이 무엇인지 한 겹 더 | 지금까지의 기본값이 대체로 여기 |
| **다정** | 두 분에게 말을 건다 | 가까운 사람만 모인 자리 |

넷이면 고르는 일이 일이 되고, 둘이면 '고른다'는 느낌이 안 난다.
셋이 사람이 한눈에 견줄 수 있는 마지막 수다.

### 2-C. 고객이 쓰는 예시도 함께

`EXVOW`(서약 7) · `EXLETTER`(편지 5) · `EXWEL`(첫인사 2).
사용자 지시: *"너무 형식적인거말고 인스타감성으로 좀 새련되게"*

**'인스타 감성'의 정의를 여기서 못 박는다** — 해시태그·이모지가 아니다.
**구체적인 기억 하나**가 들어 있고, 큰 말(영원·평생·행복) 대신
작은 말(도시락 반찬·역까지 걸어 준 길·새벽 다섯 시)로 가는 것이다.
지금 예시가 형식적으로 읽히는 이유가 정확히 그 반대다.

## 3. ★합격 기준 — 이걸 먼저 정해야 비교가 된다

두 세션이 각자 좋다고 여기는 문장을 들고 오면 취향 대 취향이 된다.
**아래 기준으로 견준다.** 기준을 못 넘으면 아무리 예뻐도 버린다.

### 나레이션 (당일 스피커로 나가는 말)

| # | 기준 | 왜 |
|---|---|---|
| N1 | 하객에게 시키는 **동작은 한 문장에 하나** | 둘을 겹치면 절반은 못 따라온다 |
| N2 | 두 분(`~해 주세요`)과 하객(`~시기 바랍니다`) **어미를 안 섞는다** | 누구에게 하는 말인지가 소리만으로 갈려야 한다 |
| N3 | **감정을 설명하지 않는다** | "감동적인 순간입니다"는 하객의 감정을 대신 정해 준다 |
| N4 | 시간 재는 말(잠시·곧)은 **한 문안에 한 번** | 겹치면 진행이 늘어지게 들린다 |
| N5 | **소리 내 읽어 3초 안에 뜻이 잡힌다** | 글로 읽는 문장이 아니라 듣는 문장이다 |
| N6 | 그 자리에서 **실제로 일어나는 일**만 말한다 | 없는 서비스를 약속하면 당일에 못 지킨다 |

### 고객 예시 (고객이 보고 자기 문장을 쓰는 글)

| # | 기준 | 왜 |
|---|---|---|
| C1 | **구체적인 명사가 하나 이상** | 그게 없으면 누구의 문장도 아니다 |
| C2 | 그대로 베껴도 **어색하지 않다** | 예시는 출발선이지 전시물이 아니다 |
| C3 | 읽는 사람이 **자기 기억을 떠올린다** | 예시의 목적은 감탄이 아니라 착수다 |
| C4 | 결(담백·눈물·다정·유머+진심·짧게)이 **한눈에 구별된다** | 결이 섞이면 고를 이유가 없다 |
| C5 | 한 사람 기준 **1분 안팎(약 300자)** 을 넘지 않는다 | 현행 화면 안내와 같은 기준 |

### 공통

- 전각 줄표(`—`) 금지 · 장식 이모지 금지 (CLAUDE.md 문구 규칙)
- 나레이션 포지셔닝 — 진행 수단이지 상품의 핵심이 아니다. 띄우지 않는다
- 근거 없는 안심 금지 — "저희가 다 해 드려요"류는 근거(누가·무엇으로)를 붙이거나 뺀다

## 5. 파일 소유권 — 충돌 0

남은 일이 전부 `order-preview.html` 과 `assets/ritual-data.js` 두 파일에 몰려 있다.
둘 다 코드를 고치면 같은 줄에서 부딪힌다. 그래서 **확정 전까지 코드는 아무도 안 고친다.**

```
docs/plans/대본개정/
  00_기획.md            ← A (이 문서)
  10_A_리서치.md         ← A 전용
  11_A_제안.md           ← A 전용
  20_B_리서치.md         ← B 전용
  21_B_제안.md           ← B 전용
  30_A가B에게.md         ← A 전용 (R2 비평)
  31_B가A에게.md         ← B 전용 (R2 비평)
  40_확정지.md           ← A 전용 (R3)
```

- 자기 번호 파일 **외에는 만들지도 고치지도 않는다.** 읽는 건 자유.
- 브랜치도 나눈다 — A는 `claude/cowork-docs-auto-deploy-f41sfk`, B는 `claude/munan-research-0814`.
- 서로의 결과는 `git fetch origin <상대 브랜치>` 로 읽는다. PR 은 R3 까지 만들지 않는다.
