# 기획 스탠바이: 마이페이지 스냅사진 파트 (2026-07-19 · 정보 수집 완료 · 방향 확정 대기)

> 목적: "예식 준비" 앞 적절한 위치에 **스냅사진 파트**를 추가하기 위한 기획 준비. 이 문서는 사이트 전역의 스냅 관련 사실을 한곳에 모은 **단일 근거 자료**다. 방향(범위·위치·대상 상품)이 확정되면 이 문서를 실제 제작안으로 승격한다.

## 0. 한눈에 — 지금 비어 있는 자리

- **사후(결과물)** 는 이미 촘촘함: 원본 도착 → 보정할 컷 번호로 선택 → 보정본 확인 → 후기. (`renderResult`, 상태 5종)
- **사전(촬영 전 스냅 기획)** 은 비어 있음: 부부가 원하는 **무드·레퍼런스·필수 컷·포즈·가족 조합**을 촬영 전에 디렉터에게 전달할 자리가 **없다.** (마케팅·문의폼에도 구조화된 필수컷/포즈/가족조합 체크리스트 없음 — 세 조사 모두 '순증 콘텐츠 필요'로 표시)
- 가장 가까운 선례: **단체 사진 구도**(`PHOTOFLOW`, guideinfo 트랙의 `photo`/`photoFx`) — 본식 뒤 Group Record용. 스냅 파트는 이 패턴을 그대로 확장 가능.

## 3. 마이페이지 구조 — 배치 후보 지점

### 최상단 여정(진행바) — 백엔드 `STAGE_FLOW` (`00_platform-config.gs:128-131`)
- **시그니처(예식) 9단계**: 신청접수 → 상담확정 → 시착 → 상담완료 → 계약완료 → 입금완료 → **제작중** → 예식완료 → 결과물전달 (+마이페이지가 '후기' 1단계 덧붙여 10-STEP 진행바 — 스크린샷의 STEP 6/10)
- **웨딩스냅 6단계**: 신청접수 → **촬영확정** → 계약완료 → 입금완료 → **촬영완료** → 결과물전달
- 스냅엔 **시착·상담완료·제작중이 없음** → 현재 제작(예식준비) 대시보드는 **시그니처 전용**.

### "예식 준비" = 제작중 단계의 Production 대시보드 (`productionDashHtml`, `mypage.html:~3800`)
현재 트랙 행 순서:
```
청첩장 · 식순 · 애프터 웨딩(선택) · 최종 확정 · 좌석 배치도(선택) · 단체 사진
 ── 확인·전달 ──
하객 안내 · 예식 확인서
```
카드 제목 "예식 준비" / eyebrow "Production". **"예식준비 전"에 스냅 파트를 넣는다는 건 이 대시보드보다 앞(위) 또는 이 대시보드 맨 앞 트랙을 뜻함.**

### 데이터 모델 (트랙 저장 방식)
- 전 제작 데이터 = Customers 시트 `제작임시저장`(col 16) **단일 JSON blob**. 새 트랙에 **새 컬럼 불필요**(공유 토큰 필요할 때만 컬럼 추가).
- 저장 액션: `apiTrackSave({action:'saveProductionTrack', track, draft, done})` → 디스패처(`consultation-booking.gs:2087`) → **`handleSaveProductionTrack`**(`80_production.gs:156`).
- 트랙 화이트리스트(`80_production.gs:162`): `dining/ritual/final/seat/guideinfo/confirm` — **새 키 추가 필요**.
- 서빙: `buildProductionState`(`80_production.gs:552`) — **웨딩스냅이면 `null` 반환(554)**, 단계 `입금완료/제작중`에서만.
- guideinfo 선례(`80_production.gs:203-218`): `{seatMode, reserveTime, reserveName, photo[≤11·≤24자], photoFx[≤8·≤24자]}` — 저장은 항상 **전체 교체**.

### 새 트랙 추가 시 바꿔야 할 지점 (GAS)
1. 화이트리스트 line 162에 새 키
2. 서버 정규화 블록(guideinfo 203-218 형태)
3. 에코백 허용목록 line 346
4. `_prodStateRev`(135-142)·`_prodUiStrip`(145-152)에 `<키>Draft` 추가
5. `buildProductionState`(575-596)에 `tracks.<키>`/`<키>Draft`
6. 프론트: `productionDashHtml` 행 + 전용 플로우(`PHOTOFLOW`가 최적 템플릿)
- **일반 persist(257-263)가 `d[track+'Draft']`·`d.tracks[track]` 자동 저장** → 배관 대부분 재사용.

### ★ 스냅 상품에도 넣으려면
- 웨딩스냅은 `제작중` 단계·Production 대시보드가 없음. 두 길:
  - (a) `handleSaveProductionBase/Track`·`buildProductionState`의 **웨딩스냅 하드리턴을 특정 새 트랙에 한해 허용**하도록 완화 + 촬영확정/입금완료 게이팅
  - (b) 스냅 전용 경량 prep 트랙 시스템 신설(pattern은 동일)

## 4. 사후(결과물) 플로우 — 이미 있는 것 (중복 방지용)
- 상태 5종: 대기 · 원본전달 · 선택완료 · 보정중 · 전달완료 (+컨펌대기/컨펌완료/추가보정)
- 부부 동선: ① 원본 보기(Drive) → ② 보정할 컷 **번호로 선택**(A안, 최소 1장) → ③ 초과 시 추가보정 결제 → ④ 보정본 → ⑤ 영상(스냅 없음) → 후기
- 관리자: 완료처리 → Drive 업로드 → 링크 등록 → 고른 컷만 보정 → 전달 → 아카이브 (`PLAN_결과물_전달_워크플로우.md`)
- **스냅 설문 스키마 분기 존재**(`_surveySchema(isSnap)`): 두 공간·촬영몰입 60~90분·셀렉트 컷·스타일링·투명성 문항.

## 5. 확정해야 할 결정(결정 대기함) — 기획 시작 전 핵심 3

1. **범위/목적** — 스냅 파트가 무엇을 하게 할지
   - (추천) **촬영 전 사전 기획**: 무드/레퍼런스(이미지·링크)·필수 컷·포즈 톤·가족 조합을 디렉터에 전달. 지금 비어 있는 정확한 자리.
   - 대안: 사후 결과물 허브(이미 있음·중복) / 사전+사후 통합 허브
2. **위치** — "예식준비 전 적절한 곳"
   - (추천) "예식 준비" 카드 **위 별도 카드**("스냅 준비") 또는 대시보드 **맨 앞 트랙 행**. 개념상 '무엇을 담고 싶은지'(스냅)가 '식 진행 준비'(예식)보다 앞.
3. **대상 상품**
   - (추천) 우선 **시그니처(예식)** — "예식준비"가 있는 상품. 이후 **웨딩스냅**에도 확장(스냅은 사전 기획이 더 중요·현재 prep 화면 자체가 없음).

### 부수 정리 필요(정본화)
- 140분 중간 구간 분배 상충(마케팅 30 vs 모달 5+25+입장20) — 문구 재사용 전 통일.
- 스냅 결과물 "N일 후 전달"의 날짜 vs 주 표기(계약 2주/4주 vs 프론트 '약 2주/4주') — 일치 확인.
- Group Record(단체 사진 구도)는 **이미 트랙 존재** → 스냅 사전 기획은 **Private Snap(부부 단독)** 중심으로 잡아 중복 회피.
