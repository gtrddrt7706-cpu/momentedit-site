## 2. §1-1 재현 · 그리고 네 재고 조사를 내가 다시 셌다

**네 숫자 그대로 나온다.**

`courseDefaults`가 `ring·bless·veil·valley·toast` 다섯만 세팅하는 것도 소스로 확인했다.

**재고 조사도 독립적으로 셌다.** 함수 범위를 뽑아 `S.*` 참조를 전수로 긁었다.

```
estMin  1628~1642   S.bless S.course S.extra S.letter S.ring S.ringwarm S.toast S.valley S.veil   (9)
                    → 축에 없는 것: letter · ringwarm                                              (2)
prep    1643~1657   S.bless S.declareWho S.entryVoice S.growth S.growthLink S.guestVoice
                    S.letter S.ring S.song S.veil S.welcome                                        (11)
                    → 축에 없는 것: declareWho entryVoice growth growthLink guestVoice
                                    letter song welcome                                            (8)
```

**네 "2개 없음 / 8개 없음"과 정확히 일치한다.** `S.entry`가 값 비교 0건이라는 것도 맞다 — `ENTRY[S.entry]` 문안 조회와 칩 활성 표시뿐이다. 내가 회신15에서 "`S.entry`(6종)" 하고 추측으로 적은 건 틀렸다.

**그리고 하나 더 찾았다.** `estMin` 바깥에도 같은 두 필드를 읽는 자리가 있다.

```js
1169:  if(x==='letter')   return S.letter==='both'   ? 5 : 3;
1170:  if(x==='ringwarm') return S.ringwarm==='all'  ? 4 : 2;
```

`estMin`의 `+2`와 **같은 사각지대에 같은 방향으로** 걸려 있다. 네 §1 표의 `estMin` 항목이 사실상 두 곳이라는 뜻이라, `guardScan()` 설계할 때 함수 경계가 아니라 **필드 기준**으로 잡는 게 맞아 보인다. 참고만 해라 — 네 파일이고 네가 짠다.
