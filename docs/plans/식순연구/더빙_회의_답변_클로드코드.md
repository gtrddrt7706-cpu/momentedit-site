## 3. Q3 · C1을 넣으면 `_exp`가 흔들리나

### 답: **(a) 아무 영향 없음.** `_exp`는 절대 손대지 마세요.

```sh
merge-guard.sh:13   _SELF=$(cd "$(dirname "$0")" 2>/dev/null && pwd)/$(basename "$0")
merge-guard.sh:37   _exp=$(grep -c '^chk ' "$_SELF")
```

`_exp`는 **하드코딩 상수가 아니라 매 실행마다 자기 파일을 세는 동적 값**입니다. 저장소 어디에도 숫자가 박힌 곳이 없습니다. 그리고 세는 대상은 `merge-guard.sh` 자신의 `^chk ` 줄이라 `check-ritual-mirror.js`는 애초에 무관합니다.

```sh
merge-guard.sh:574  node scripts/check-ritual-mirror.js || fail=1
```

`check-ritual-mirror.js`는 **종료코드만** 소비됩니다. stdout은 캡처·카운트되지 않습니다. 게다가 `ok()`의 출력 접두사는 `'ok '/'FAIL '`이라 `'^chk '` 패턴과 문자열 자체가 다릅니다.

**실측으로 확인했습니다.** `origin/main`을 임시 worktree로 떠서 `check-ritual-mirror.js`에 `ok(...)` 1줄을 추가하고 돌렸습니다. → `rc=0` · 출력 404줄 → 405줄 · 마지막 줄 `ALL MARKERS OK`. diff는 `ok` 한 줄 추가뿐이었습니다.

**신경 쓸 건 하나뿐입니다**: 새 `ok()`의 **조건이 참인지**. 거짓이면 `fail=1 → exit(1) → 574행 || fail=1`로 가드가 정상적으로 RED가 됩니다. 이건 카운트 파손이 아니라 검사 실패입니다. 그래서 아래 Q6에서 MIN 문제를 같은 PR에 넣자고 하는 겁니다.
