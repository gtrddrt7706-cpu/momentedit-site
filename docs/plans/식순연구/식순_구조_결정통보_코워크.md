## 1. 결정 1 · 가족 코스 첫인사 `welcome at:3 → at:2` — **착수 허가**

**사용자 결정(2026-07-27): "추천대로 하자."** 코스설계_v1의 공통 자물쇠(`입장 → 환영·첫인사 → 본문`)를 따른다.

```js
// assets/ritual-data.js + order-preview.html 인라인 사본, 양쪽
family.opt = [{k:'welcome', at:3}]   →   [{k:'welcome', at:2}]
```

### 1-1. ★`at` 두 글자만 고치면 낭독 음성이 거짓말을 한다

지금은 가족 코스에서 덕담이 **항상 첫 순간**이라 `BLOCK.bless`가 트는 나레이션 "오늘 예식의 문은, 두 사람을 가장 오래 지켜봐 오신 부모님의 말씀으로 엽니다"가 첫인사 ON/OFF 양쪽에서 사실이다. `at:2`가 되면 **첫인사를 켠 고객에게** 이 문장이 나가는 시점에 두 사람은 이미 인사를 마친 뒤다.

화면 문구가 아니라 **실제로 스피커에서 나가는 문안**이라 심각도가 높다. 하객이 방금 들은 것과 다른 말을 스피커가 한다.

**그래서 `at` 변경과 아래 판정 리팩터는 반드시 한 커밋으로 간다.** 나눠서 병합하면 그 사이 배포분이 거짓 나레이션을 내보낸다.

### 1-2. ★★`famOpen`이 두 가지 뜻을 겸하고 있다 — 여기가 함정

`famOpen`은 `order-preview.html`에 **두 군데** 있다. `BLOCK.bless`(:1422)와 카드 렌더 분기 `else if(k==='bless')`(:1216). 그리고 같은 변수가 서로 다른 질문에 답한다.

```js
// :1216
var famOpen=(S.course==='family');
var blessNar=famOpen?'오늘 예식의 문은…':'이제, 두 사람을…';                                  // (A)
var onCard =oc('bless','on','넣기',(famOpen?'예식의 문을 여는, 이 코스의 시그니처 순서예요'
                                           :'부모님이나 가족 어른이 짧게 말씀을 전해요'), …);   // (A)
var offCard=oc('bless','off','빼기',(famOpen?'덕담 없이 서약으로 바로 이어져요'
                                           :'편지와 폐식 인사에서…'), …);
h+=famOpen?(onCard+offCard):(offCard+onCard);                                                 // (B)
```

| | 실제로 묻는 것 | `at:2` 후 |
|---|---|---|
| **(A) 위치 의미** — `blessNar` · `BLOCK.bless.nar` · `cue` · "예식의 문을 여는" 카피 | 덕담이 이 예식의 **첫 순간**인가 | **위치 기반으로 교체** |
| **(B) 코스 정체성 의미** — `onCard+offCard` 배열 순서(권장 기본값을 먼저 보여줌) | 이 코스가 **가족 코스**인가 | **코스 기반 유지** |

**`famOpen` 하나를 통째로 위치 기반으로 갈아치우면 (B)까지 따라 뒤집힌다.** 첫인사를 켠 가족 코스 고객에게 '빼기' 카드가 먼저 나오고 '넣기'가 뒤로 밀린다. 덕담이 이 코스의 중심이라는 설계와 정반대이고, 화면만 봐서는 원인을 짚기 어려운 회귀다.

### 1-3. 제안 · 변수를 둘로 쪼갠다

```js
var famCourse = (S.course==='family');                                                  // (B)
var _o = curSeq();
var _first = _o.filter(function(k){ return k!=='guest' && k!=='veil' && k!=='entry'; })[0];
var blessOpens = (_first === 'bless');                                                  // (A)
```

`guest`(식전 안내)·`veil`(베일 다운)·`entry`(입장)는 개식 이전이거나 개식 자체라 "문을 연다"의 대상에서 뺀다. `:1216`과 `:1422` 두 곳에 같은 두 변수를 두고, (A) 쪽을 전부 `blessOpens`로, `h+=…?(onCard+offCard):(offCard+onCard)` **한 줄만** `famCourse`로 둔다.

결과 판정표:

| 경우 | `blessOpens` | 나레이션 | 사실인가 |
|---|---|---|---|
| 가족 + 첫인사 OFF | true | "오늘 예식의 문은…" | ✓ 덕담이 첫 순간 |
| 가족 + 첫인사 ON (`at:2`) | false | "이제, 두 사람을…" | ✓ 인사가 먼저 |
| 담백·미니멀·축하 (덕담이 편지 뒤) | false | "이제, 두 사람을…" | ✓ |
| 타 코스에 팔레트로 덕담 추가 | false | "이제, 두 사람을…" | ✓ (지금도 이 결과지만 우연) |

**이건 §2-4의 `_afterLetter` 위치 기반화와 같은 리팩터다.** 두 판정을 함께 넣으면 `cue`가 네 갈래로 정확해진다 — 대독이면 대독 큐 / `blessOpens`면 "문을 여는 말씀" / `_afterLetter`면 "편지 뒤라 한 톤 낮춰" / 둘 다 아니면 위치를 언급하지 않는 중립 큐. **§2-4와 §2-5를 한 PR에 담는 게 낫다.**

**건드리지 말 것** — `estMin()`(:1442)의 `var bd=(S.course==='family')?'on':'off'`는 **덕담 토글의 코스별 기본값**을 보는 것이라 위치와 무관하다. `BLOCK.bless` 첫 줄 `if(S.bless!=='on') return null`도 그대로.
