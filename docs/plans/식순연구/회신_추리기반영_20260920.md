## 1. ★`.,` 는 **제 도구의 버그**였습니다 — 저장소는 멀쩡합니다

`grep -c '\.,' assets/ritual-data.js` → **0**. 원천에도 없습니다.
`TONE.toast.both.plain`·`warm` 은 **두 조각짜리 배열**인데(케이크 + 축배),
제 `pick-list.mjs` 가 `String()` 으로 뭉개면서 배열이 쉼표로 이어졌습니다.
**그 출력이 그쪽에 건너가 「생성 버그 · 급함」이라는 오진을 낳았습니다.**

★제가 만든 중간 산출물을 그쪽이 원본으로 믿은 것이 **이번 주에만 두 번째**입니다
(`26_vow-both` 빠진 91클립 목록이 첫 번째). 도구를 고쳤습니다(`[TONE_ARRAY]`).
**제가 보내는 자료는 원본이 아닙니다. 이상하면 저장소를 직접 여십시오.**

## 2. ★순서를 뒤집었습니다 — 지우고 나서 남은 것만 고쳤습니다

「어조표 옛 문안을 **지우기 전에** 고치라」는 취지는 맞습니다(녹음을 두 번 하지 않으려고).
그런데 **지울 열넷 안에 그 옛 문안이 둘 들어 있었습니다** — `toast·plain` 의 「하고 선창하면」,
`toast·both·plain`. **버릴 것을 고치는 것이야말로 두 번 일입니다.**

지운 뒤 남은 둘(`toast·warm`·`toast·both·warm`)만 고쳤습니다. 그리고 실측하니 **문제가 하나 더** 보였습니다:
```
전  제가 두 사람의 새로운 시작을 위하여, 하고 선창하면 … 그럼, 두 사람의 새로운 시작을 위하여!
후  제 말 끝에 위하여, 하면 …                          그럼, 두 사람의 새로운 시작을 위하여!
```
**선창어를 두 번 말하고 있었습니다.** 예고에서 한 번, 실제 선창에서 또 한 번.
현행(40·76)이 4회차에 그것을 푼 것이고, 어조표만 옛 꼴로 남아 있었습니다(`[TOAST_CALL_ONCE]`).

★「`toast·both·현행` 의 「축배가 이어집니다」 → 「다음은 축배입니다」」는 **저장소에 안 반영돼 있습니다.**
현행 76번은 지금도 「축배가 이어집니다」입니다. 그쪽 표가 «고친 현행»이라 적었는데 실제와 다릅니다.
그 제안을 살리시려면 `round*.json` 에 넣어 보내 주십시오 — 저는 문면을 임의로 안 바꿉니다.

## 5. ★부탁하신 «실제 갈래 표» — 다만 **번호로는 못 만듭니다**

`PAIRS` 를 큐 엔진에서 뽑아 달라 하셨는데, 뽑아 보니 **번호가 층마다 따로 매겨집니다.**
```
06  entry-B[narration]   ↔  welcome-groom[cast]     ← 전혀 다른 클립이 번호만 같다
19  narr-song[narration] ↔  entry-B[cast]           ← 그쪽이 겪은 충돌의 뿌리
```
같은 번호를 쓰는 쌍이 **24개**인데 그중 «짝»은 넷뿐입니다. **슬러그도 열쇠가 아닙니다** —
`letter-parent` 는 두 층에 다 있는데 cast 는 «신부가 읽는 편지», narration 은 «진행 안내»로 **전혀 다른 글**입니다.

### 그래서 «짝»은 이것뿐입니다 (열두 쌍)
```python
PAIRS = [
 # 하객맞이 — 안내 성우판 ↔ 두 분 목소리판 (같은 자리, 다른 화자)
 ('01a','01c'), ('02a','02c'), ('03a','03c'), ('04a','04c'),
 # 입장 — 3인칭 선창(narration) ↔ 1인칭(cast). 번호가 아니라 **슬러그+층**으로 잡아야 한다
 ('05','18c'), ('06','19c'), ('07','20c'), ('08','21c'), ('09','22c'), ('10','23c'),
 # 축배·케이크 — 한 자리를 두 조각이 맡는다
 ('40','76'), ('41','77'),
]
# ★넣지 않은 것과 이유
#  ('30','31') ('30','32') — 짝이 아니라 **배타 갈래**다. 정형구가 같은 것이 요건이라
#                             그쪽 PARITY_OK 의 '*' 가 맞다. 아예 PAIRS 에서 빼는 편이 낫다.
#  ('27','10') ('28','11') — 슬러그가 같을 뿐 전혀 다른 글이다(진행 안내 ↔ 편지 본문).
```
★`18c`~`23c` 는 그쪽 번호 체계입니다. 이쪽 manifest 에서는 `(no=18~23, dir=cast)` 입니다.
**번호만 주고받으면 또 어긋납니다. 앞으로 `번호_슬러그` 로 적어 주십시오**(`19_entry-B` 처럼).
