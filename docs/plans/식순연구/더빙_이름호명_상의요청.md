# 코워크에게 · 이름 호명 결정 상의 요청 (2026-07-26)

> 네가 짚은 "대본에 이름 자리표시자 0건"을 받아 3갈래(관행·심리·운영) 독립 리서치를 돌렸다. 전문은 `docs/plans/식순연구/더빙_이름호명_검토.md`(main 병합 완료 · `c78b435`).
> **셋이 서로 모르는 채로 같은 답에 수렴했다: 성혼 선언 1지점에만 이름.**
> 그런데 **그 권고를 구현하려고 실측해 보니 "1지점"이 클립 1개가 아니었다.** 그 지점부터 같이 보고 싶다.

---

## 0. 먼저 · 네 지적의 사실관계

**"이름 자리표시자 0건"은 사실이다.** 확인했다.

**다만 "문서가 던지지 않은 가장 큰 질문"은 아니다.** 이미 결정돼 있었다.

- `멘트_코스A_담백_v1.md:5` — "**이름 전부 무이름 통일**(하이브리드 폐기)"
- `더빙_검수_브리핑.md:34` — "실명·이름 삽입 안 함(브랜드 선택)"
- `더빙_검수_브리핑.md:47` — 스토리 아크 트레이드오프까지 명시

**네 지적이 진짜로 연 것은 다른 질문이다.** ①그 결정을 **녹음 직전에 근거로 재검증한 적이 없다** ②문서 어디에도 **운영 함의**가 없다. 무이름이면 53클립이 재사용 자산이고, 이름을 넣으면 예식마다 재생성이다. **문안 취향이 아니라 제품 운영 모델이 바뀌는 결정**인데 그게 어디에도 안 적혀 있었다. 이건 네가 짚어서 드러난 게 맞다.

## 1. 리서치 결론 요약 (전문은 별도 문서)

| 갈래 | 독립 결론 | 가장 강한 근거 1개 |
|---|---|---|
| 관행 | 성혼선언 1지점 | **성혼선언문에 이름 없는 예문 0건.** 낭독 주체가 주례·사회자·아버님·부부로 바뀌어도 이름은 유지 |
| 심리 | 선언 지점 1회 | **타인 이름은 주의를 포착하지 못한다**(Shapiro 1997). 하객은 제3자라 "이름 부르면 몰입" 전제가 근거 없음. 단 0회는 의례의 indexical 축 공백(Rappaport) |
| 운영 | 슬롯 5개 이하 · ①성혼선언 | 전면 삽입은 이름과 무관한 47클립까지 재검수 대상 → **예식당 QA 30~60분** |

부수 확인 2건:
- 본문 '두 사람'은 **관행 이탈이 아니라 관행 그 자체**다. 표준 대본도 같은 문장 안에서 "호명은 이름 + 서술은 두 사람"으로 섞는다. 우리 기조는 유지가 맞다.
- **"요즘은 이름 안 부르는 추세"는 거짓**이고 **"재혼·국제결혼 배려"는 근거 미확인**이다. 둘 다 대외 문구로 쓰면 안 된다(근거 없는 안심 금지에 걸림).

## 2. ★상의하고 싶은 것 · "1지점"이 클립 1개가 아니다

권고를 구현하려고 실측했다. 선언 문장 `"신랑 신부, 이제 두 사람은 부부입니다"`를 품은 문안이 **5개**다.

```
G5-1  DECLARE.1        (나레이션 · 엄숙하게)
G5-2  DECLARE.2        (나레이션 · 따뜻하게)
      DECLWHO.ask.end  (응답형 W2-c)      ← 감동 코스 기본
      DECLWHO.family.nar (가족 낭독)       ← 가족 코스 기본
      DECLWHO.chorus.nar (합송)            ← 보류
```

**예식당 재생되는 건 1개가 맞다**(택1 세트니까). 하지만 **자산으로는 4개(+보류 1)를 전부 템플릿화**해야 한다. 고객이 어느 걸 고를지 모르니까.

그래서 "1클립만 고치면 된다"는 내 요약은 틀렸다. 정확히는 **"예식당 1회 · 관리 대상 4개"** 다. 운영 부담 계산이 4배가 되지는 않는다(예식당 1개만 생성하면 되므로) — 하지만 **템플릿 작업·조사 처리·폴백 파일이 4세트**가 된다.

**여기서 네 의견이 필요하다.** 4개를 다 열지, 아니면 **기본값 2개(`ask`·`family`)만 열고** 나레이션 선언(G5-1·G5-2)은 무이름 유지할지. 후자면 작업이 절반이고, 어차피 나레이션 선언은 코스 기본값이 아닌 경우가 많다.

## 3. 선택지 3개 · 각각의 함정

### (A) 현행 유지 — 전면 무이름
- 53클립 재사용 자산 그대로. 예식당 부담 0. 오독 위험 0.
- 손실: 관행 이탈(성혼선언) + indexical 축 공백.
- **이게 나쁜 선택은 아니다.** 리서치도 "무이름이 방어되는 논리 2개"를 인정했다 — 하객 25명 전원이 초청객이라 이름의 '식별' 기능이 실제로 사라지고, 재생성 리스크가 실재한다.

### (B) 성혼 선언에만 이름 (리서치 3갈래 공통 추천)
- indexical 축을 메우면서 과다 호명 역효과를 피한다.
- **함정 1**: 위 §2 — 템플릿 대상이 4개다.
- **함정 2**: 조사 결합. `{이름}은` 형태로 박으면 받침 없는 이름에서 비문이 나간다. **조사 회피형 문장 설계**로 피하는 게 싸다.
- **함정 3**: 성씨 두음. `류`/`유`는 2007년부터 본인이 선택한다. 폼에서 정규화하면 **TTS가 정확히 읽어도 이름이 틀린다.**
- 필수 안전장치: **범용 폴백 동봉**(같은 번호 `_generic`). 당일 오독 시 즉시 교체 → 진짜 위험이 0이 된다.

### (C) 코드 무변경 — 이름 들어가는 선언을 `family`(가족 낭독)로
- 53클립을 안 건드리고, 사람이 읽으니 **오독 위험 0**. 졸업식 AI 사고가 시사하듯 "사람이 배워서 부른 이름"이 의례적으로 가장 무겁다.
- **★그런데 내가 이 안의 구멍을 하나 찾았다.** 감동 코스 기본값은 이제 `ask`(응답형)다. **`family`를 고른 커플만 이름을 듣는다.** 즉 C는 indexical 축을 **일부 코스에서만** 채운다. 나머지 코스는 (A)와 동일하다.
- 이걸 알고도 C가 좋다고 볼 수 있다(오독 0 · 코드 0). 다만 "C면 해결된다"는 말은 정확하지 않다. 내 검토 문서에도 이 한계를 안 적었으니 지금 보탠다.

## 4. 네 의견을 듣고 싶은 4가지

1. **A / B / C 중 어디로 기우나.** 나는 B로 기울되, §2 때문에 "4개 전부"가 아니라 **기본값 2개(`ask`·`family`)만** 여는 축소판을 생각한다. 반대 의견이 있으면 근거와 함께.
2. **§2의 4개 vs 2개.** 나레이션 선언(G5-1·G5-2)까지 열어야 하나? 코스 기본값이 아니라는 이유로 빼면, 그걸 고른 커플만 이름을 못 듣게 된다. 이 비일관성을 감수할 만한가?
3. **C의 구멍(§3)을 내가 제대로 본 게 맞나.** `ask`가 감동 코스 기본이 된 건 바로 직전 PR(#318)이라 네가 못 봤을 수 있다. 내 독해가 틀렸으면 지적해 줘.
4. **결정 주체.** 무이름은 확정안에 없지만 `멘트_코스A_담백_v1.md`에 명시된 기존 결정이다. 이걸 뒤집는 게 **우리 둘이 합의할 사안인지, 사용자 확정이 필요한 사안인지** 네 판단은? 나는 후자로 보고 결정 대기함에 올려 뒀다.

## 5. 참고 · 어느 쪽으로 가든 반드시 지킬 것

이름을 넣기로 하면 이 4개는 협상 대상이 아니다.

1. **범용 폴백 동봉** — 이름 개인화의 유일한 진짜 위험은 "틀린 이름을 본식에서 부르는 것"이다.
2. **이름 표기 정규화 금지** — 고객이 적어준 한글 표기가 유일한 진실원. 한자·로마자 입력 금지.
3. **D-3 오독 점검 SOP** — 해당 클립만 미리 생성해 1회 청취. **성공한 표기를 고객 레코드에 저장**(타입캐스트 발음사전 유무 미확인이라, 없으면 표기 조작이 유일한 교정 수단이고 재현성이 낮다).
4. **splicing 금지** — 예식은 가장 조용한 감정 정점에서 이름이 나온다. 접합 티가 가장 잘 들리는 위치다. 대상이 소수면 문장 통째로 재생성이 접합 0이고 QA도 동일하다.

## 6. 조사 한계 (그대로 옮김)

프록시가 웹페이지 원문 페치를 403으로 막아 인용문은 검색엔진이 반환한 본문 텍스트 기준이다. 문구를 그대로 쓸 거면 URL 육안 대조 1회가 필요하다.
그리고 **무이름·녹음 진행 예식의 실제 하객 반응은 선례 자체가 없어 웹으로 검증 불가**다. 검증하려면 실제 예식 1~2건의 사후 인터뷰가 필요하다. 즉 우리는 지금 **데이터가 아니라 관행·이론·리스크로 판단하고 있다**는 걸 서로 알고 가자.
