# 더빙 — 발주 전 준비 상태 (짧게 유지할 것)

> **녹음에 쓰는 문서는 이 파일이 아니다.** 문안·파일명·톤·무음·리테이크 우선순위·녹음하지 않는 것 —
> 성우(또는 TTS 오퍼레이터)에게 필요한 건 전부 `docs/plans/식순연구/더빙_녹음_대본_최종.md` 한 곳에 있다.
> 그 파일은 `assets/ritual-data.js`에서 문안을 직접 읽어 자동 생성되므로 사이트와 절대 어긋나지 않는다
> (`node scripts/build-dubbing-script.mjs`).
>
> **이 파일에 남은 것**: 대본에 담을 수 없는 것 — 아직 사지 않은 것, 아직 넣지 않은 음원, 저지른 실수의 기록.
> 여기에 문안이나 연출 지시를 다시 적지 말 것. `scripts/check-dub-sheet.js`가 막는다.

## 왜 이 파일이 이렇게 짧아졌나 (2026-08-01)

예전엔 이 시트가 클립 목록·문안·톤·무음 설계를 통째로 들고 있었다. 자동 생성 대본도 같은 것을 들고 있었다.
**같은 사실을 두 곳이 각자 적고 있었고, 조용히 갈라졌다.** 대조해 보니 어긋난 곳이 여덟이었고, 그중 넷은 그대로 녹음했으면 사고였다:

- 축배 파일명을 `toast-cheer`로 적어 뒀는데 엔진(`assets/ritual-cue.js`)은 `toast-toast`를 찾는다 → **축배 클립만 조용히 안 나간다.**
- 폐식 직후 안내가 폐기된 구 문안이라 "자리에서 그대로" 바로 뒤에 "자리를 옮기실 때"가 나온다 → **정반대 안내.**
- 성혼 선언의 정적 위치를 "마지막 문장 앞"이라고 적어 뒀다. 선언문은 **끝에서 두 번째** 문장이다
  (마지막은 박수 요청) → 그대로 편집하면 **정적이 박수 요청 앞에 붙어 정점이 어긋난다.** 2026-07-26에 한 번 고쳤던 실수가 되살아나 있었다.
- G3-14L(덕담이 길었을 때 쓰는 마무리)을 "G3-14와 같은 호흡으로 찍으라"고 적어 뒀다. 정반대다 —
  한 예식에서는 둘 중 하나만 나가므로 하객은 둘을 나란히 듣지 않는다. 톤을 맞추면 G3-14L이 존재할 이유가 사라진다.

원인은 전부 하나다. 두 곳이 같은 것을 적었다. 그래서 한 곳으로 줄이고, 나머지는 이 파일에서 지웠다.
지운 내용이 사라진 게 아니라 **생성기(`scripts/build-dubbing-script.mjs`)로 옮겨 갔다** — 이제 대본을 다시 뽑으면 항상 함께 나온다.

## 아직 안 된 것

### 음원 배선

- `parents.html` — `/assets/audio/parents-letter.mp3` 자동 재생 슬롯 **배선 완료**. 음원 파일만 넣으면 '듣기' 버튼이 그 음원을 재생한다.
- 식순 클립 — 현재 **텍스트 카드 모드**. 콘솔(`console.html`)과 미리듣기 엔진은 오디오가 0개여도 끝까지 돌아간다.
  `assets/audio/`에 번호대로 넣는 만큼 자동으로 소리가 붙으므로, **54개가 다 모일 때까지 기다릴 필요가 없다.** 한 개씩 넣어도 된다.
- `assets/audio/` 디렉터리 자체가 아직 없다. 첫 음원을 넣을 때 만든다.

### 결정 대기

- **유료 플랜 벤더 1곳 선택** (라이선스 근거는 대본의 '벤더 · 라이선스' 절에 있다). 첫 예식 전 필수.
- **목소리 A/B** — `G4-parent`·`W2-b` 두 클립만 후보 벤더별로 뽑아 비교한다. 30분·0원이면 끝나고, 이게 정해지기 전에는 나머지 52개를 못 찍는다.
- **BGM 구독 1곳** — 나레이션과 별개 결정이지만 같은 날 정해 두는 편이 낫다.
