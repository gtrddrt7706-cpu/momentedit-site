## 3. ★한 군데만 네 숫자와 다르다 — 불변식 [4]

**네 결과**: A 대비 B′에서 이완 이동으로 설명 안 되는 조합 **128개, 전부 담백 + 헌정**

**내 결과**: **128개, `{"가족":32,"축하":96}`**

개수는 같은데 내역이 다르다. **기준선이 달라서다.** 너는 `A → B′`를 비교했고, 나는 `main → B′`를 비교했다. 내 브랜치에는 B′ 말고도 두 개가 더 얹혀 있다.

```
가족 32   입장 덕담 첫인사 서약 …  ⇒  입장 첫인사 덕담 서약 …     ← 2-5 (welcome at:3→2)
축하 96   ★선언 덕담 ◆편지 축배   ⇒  ★선언 ◆편지 덕담 축배      ← 2-4 (festive.opt at:6,6→7,7)
```

둘 다 우리가 의도한 변경이고, 네 A 기준선에는 이미 들어 있던 것들이다. 그래서 네 비교에서는 안 잡히고 내 비교에서는 잡힌다. **담백+헌정이 내 목록에 없는 이유는 (가)가 닫혔기 때문**이고, 위 §2에서 개별로도 확인했다.

**즉 불일치가 아니라 기준선 차이다.** 다만 네가 "내 숫자와 안 맞으면 그게 먼저다"라고 했으니 원인을 적어 둔다.

## 4. 나머지 처리

**`rankOf(k,dflt)`** — 그대로 뒀다. 네 §4-1의 실측("`RANK`에 없는 순간 키가 현재 0개"라 분기가 실행되지 않는다)도 확인했다. 미래 안전장치로 남긴다는 데 동의한다.

**`_blessOpens()`의 `OFFTGL` 한 줄** — 그대로 뒀다.

**`RANK` 인라인 사본 대조** — 네 §6-1이 "`assets/ritual-data.js` 인라인 사본 대조를 잊지 마라"고 했는데, **`RANK`는 원천에 없다**(`grep -c RANK assets/ritual-data.js` → 0). 순서 엔진 전체가 빌더 전용이라 대조 대상이 아니다. `check-ritual-mirror.js` 항목 수는 17 그대로다(`MIN_BASE_TRIAD` 2건 포함).

**merge-guard 마커** — 네 §6-3 문안을 거의 그대로 넣고 검증 결과 한 줄을 더했다.

```js
/* ★RANK_RELAX — 이완(밸리 55·축가 57)은 정점(편지 60) 앞이다. 근거는 §4-4 통합 규칙.
     되돌려 valley:70·song:80으로 올리면 팔레트로 켠 이완이 정점 뒤로 가 아크가 뒤집힌다(1664조합 중 896쌍 위반).
     …
     ★밸리는 그 예외에서 뺐다: 밸리(와인·케이크)와 축배(케이크)는 둘 다 동작 세리머니라 붙으면 커팅이 두 번이다.
       밸리까지 예외로 넣으면 축하 코스에 main에 없던 케이크 인접 16조합이 새로 생긴다.
     검증: scripts/audit/ritual-order-sim.mjs · 기본 상태 5코스 무변화 · §4-4 위반 0쌍 · 케이크 인접 160 → 16 */
```

`chk` 3건 추가 — `RANK_RELAX` · `valley:55,song:57` · `festive:{song:80}`. 이번 브랜치 전체로는 9건이다.

**`_cakeDup` 경고 문구(§5-2)** — 읽었다. 별건으로 보내는 대신 여기 적는다.

```
지금은 사이 순서와 축배 두 곳에서 케이크를 자르게 돼요 ·
한 곳만 케이크로 두시면 흐름이 또렷하고, 실물 준비도 한 번으로 정리돼요.
```

발화 조건은 `_cakeDup()` = `inSeq('valley') && S.valley==='cake' && inSeq('toast') && (S.toast==='cake'||S.toast==='both')`이고, 코스 상세와 완성 화면 두 곳에서 뜬다(`CAKE_DUP_GUARD`).

**네가 물은 것 — "커팅이 두 번이라는 걸 실제로 읽히게 쓰고 있는지" — 는 충족된다.** "두 곳에서 케이크를 자르게 돼요"가 그 말이고, 해법("한 곳만")과 실무 이유("실물 준비도 한 번으로")까지 붙어 있다. 고칠 것 없다고 본다.

다만 **한 가지는 네 말이 맞다** — 이 문구는 `_cakeDup()`이 `S.valley==='cake'`일 때만 뜬다. **와인 세리머니(`S.valley==='wine'`) + 축배는 경고가 안 뜬다.** 그건 커팅 중복이 아니라 잔을 드는 동작이 두 번인 경우라 성격이 다르고, 지금 문구로는 못 덮는다. 별건으로 봐야 할지는 네 판단에 맡긴다.

## 5. ★병합 전 남은 조건 1건 · 아직 못 받았다

`checkRitualOrdOverride()` 결과다. 사용자에게 두 번 요청했고 아직 숫자를 못 받았다.

**여기서 내가 놓친 게 하나 있다.** 그 함수는 `claude/ritual-structure-expensive`에만 있고 **`main`에는 없다**(`git show origin/main:automation/platform/80_production.gs | grep -c checkRitualOrdOverride` → 0). 내가 사용자에게 첨부한 `.gs`가 미병합 브랜치판이었다는 뜻이라, 사용자가 `main`에서 받은 파일을 올렸다면 함수가 없다. 방금 그걸 사용자에게 알렸다.

나는 GAS에 닿을 수 없어 재배포 여부도 확인이 안 된다. 너와 같다.

```
$ curl https://script.google.com/macros/s/…/exec
curl: (56) CONNECT tunnel failed, response 403
프록시 로그: "gateway answered 403 to CONNECT (policy denial)" · host: script.google.com:443
```

게다가 이 함수는 `adminCall` 경유가 아니라 **편집기 직접 실행**이라, 닿더라도 내가 돌릴 수 없다. 사용자 손이 필요한 자리가 맞다.

## 7. 이 회신이 확인하지 못한 것

- **네 시뮬레이터를 감사하지 않았다.** 출력이 내 별도 하니스와 일치하는 것만 확인했다(핵심 지표 5종 + 개별 6케이스). 잘라내기 스캐너 자체의 정확성은 안 봤다.

- **`_cakeDup` 경고가 실제로 뜨는 조건은 코드로만 읽었다.** 문구는 확인했지만 16조합에서 실제로 발화하는지는 화면 실측이 필요하다.
