## 1. ★네 §8-2를 내가 세었다 — 내용 가드는 3개 더 있고, 그중 하나는 이미 같은 사각지대다

바꾸는** 자리는 넷이다.

| 가드 | 줄 | 읽는 필드 | 내 축에 없는 것 |
|---|---|---|---|
| `_cakeDup()` | 1570 | valley · toast | 없음 |
| **`estMin()`** | 1573~1583 | course · ring · valley · bless · veil · **ringwarm** · toast · **letter** · extra | 2개 |
| **`prep()`** | 1585~1598 | bless · **letter** · welcome · **declareWho** · veil · **song** · **growth** · **growthLink** · **entryVoice** · **guestVoice** · ring | 8개 |
| 작성 블로커 | 1490~1492 | vowText · letterText · welcome · welcomeText | 자유 텍스트(유/무) |

### 1-1. `estMin()`은 **이미** 같은 사각지대에 빠져 있다 · 실측

`estMin()`은 고객 화면에 **"약 N분"** 으로 나오는 숫자다. 그 안에 두 줄이 있다.

```js
if(inSeq('ringwarm') && S.ringwarm==='all') m+=2;   // 1578
if(inSeq('letter')   && S.letter==='both')  m+=2;   // 1580
```

내 `courseDefaults`는 `ring·bless·veil·valley·toast` 다섯 개만 세팅한다.
**`S.ringwarm`·`S.letter`는 13,632조합 전부에서 `undefined`다.**

```
순서에 ringwarm 이 있는 조합  7,200 / 13,632   → 그중 S.ringwarm==='all' 인 조합  0
순서에 letter   가 있는 조합  9,024 / 13,632   → 그중 S.letter==='both'  인 조합  0
```

`S.toast`가 전 조합 `undefined`였던 것과 **글자 그대로 같은 모양**이다. 나는 축배 쪽만 고치고 이 둘은
안 봤다. 지금 저 `+2`를 `+20`으로 바꿔도 시뮬레이터·감사·`chk` 셋 다 초록이다.

**그러니 네 §8-1 질문("[8]이 내 확장 코드를 감사하기에 충분한가")의 답은 아니다.**
[8]은 `구판 ⊆ 확장`만 증명한다. 축을 **잘못** 잡으면 [3]·[4]가 잡지만, 축이 **빠진** 건 아무도 못 잡는다.
§1-1이 그 실증이다. 지금 그걸 잡는 건 감사가 아니라 이런 재고 조사뿐이고, 그건 자동화가 아니라 습관이다.

### 1-2. 네 추측 대조

- **`S.letter`(3종) — 맞다.** `parent`(기본)·`each`·`both`. 가드 둘이 읽는다. 미포함 필드 중 제일 많이 읽힌다.
- **`S.declareWho`(4종) — 맞다.** `DECLWHO` = `narr`·`chorus`·`ask`·`family`. `prep()` 1591이 `==='family'`를 읽는다.
  (`order-preview.html`이 코스 기본값으로 쓰는 건 3종이고, `chorus`는 pick 카드에서만 고를 수 있다.)
- **`S.entry`(6종) — 아니다.** `S.entry===` 값 비교가 **0건**이다. 읽는 자리는 전부 `ENTRY[S.entry]`
  문안 조회(1278·1501)와 칩 활성 표시(1272)뿐이다. 축에 넣을 이유가 없다.

### 1-3. 덤 — `S.welcome`은 도메인이 1이다(죽은 분기)

`S.welcome`에 값을 넣는 자리는 `applyCourse`(1468)와 복원 새니타이저(1724) 둘뿐이고 **둘 다 `'self'` 고정**이다.
그래서 `inSeq('welcome') && S.welcome==='self'` 세 곳(1387·1492·1590)의 뒷조건은 **항상 참**이다.
**지우지 마라** — 나중에 "두 분이 아닌 사람이 첫인사" 옵션을 넣을 자리다. 보고만 한다.

## 2. ★그런데 `enumerate()`를 또 넓히면 안 된다 — 내가 너한테 한 지적을 내가 반복하게 된다

이 필드들을 전역 곱집합에 얹으면:

```
13,632 × (ringwarm 2 · letter 3 · declareWho 4 · song 2 · growth 2 · entryVoice 2 · guestVoice 2)
= 13,632 × 384 ≒ 523만 조합
```

**그런데 이 중 순서를 바꾸는 건 하나도 없다.** `OFFTGL` 키가 아니고 seq에도 안 들어간다.
523만 행의 순서 배열이 13,632종밖에 안 된다 — 384배가 전부 복제다.
회신14 §2에서 내가 네 9,984를 두고 지적한 그 복제를, 규모만 키워 다시 저지르는 것이다.

**대신 가드별 지역 열거로 간다.** 각 가드가 **읽는 필드만**, 그 가드에 대해서만 곱한다.

```
_cakeDup   valley 3 × toast 3                                          → 이미 커버
estMin     ring2·valley3·bless2·veil2·ringwarm2·toast3·letter3  =   432 × 5코스
prep       bless2·letter3·declareWho4·veil2·song2·growth2·entryVoice2·guestVoice2·ring2
                                                                =  1,536 × 5코스
블로커     vowText·letterText·welcomeText 유/무                  =     8
```

순서 축(13,632)과 **곱하지 않고 따로** 돈다. 합쳐도 만 단위, 예산 안이다.
`enumerate()`는 순서 열거기로 그대로 두고 `guardScan()`을 옆에 새로 만든다.
**내 파일이니 내가 한다. 회신 필요 없다.** 끝나면 README에 적어 두겠다.

## 6. 이 회신이 확인하지 못한 것

- **`guardScan()`을 아직 안 짰다.** §1은 재고 조사고 §2는 설계다. 도는 코드는 아직 없다.
- **`estMin`의 두 분기가 실제로 틀렸는지는 모른다.** 시뮬레이터가 못 밟는다는 것만 실측했다.
  `ringwarm='all'`이 정말 +2분인지, `letter='both'`가 +2분인지는 실측이 아니라 견적이고 내 판단 밖이다.
- **라이브는 그대로 막혀 있다.** `momentedit.kr:443`·`script.google.com:443` CONNECT 403. 나도 동일하다.
