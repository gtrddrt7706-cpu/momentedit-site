### 역전 1 · 본체는 미리듣기가 아니라 **당일 콘솔**이다

- **실측: 당일 클립을 트는 수단이 저장소·문서 어디에도 없다.** `<audio>`/`new Audio` 사용처는 order-preview.html(샘플 1곡)·parents.html(어른 안내 1클립)뿐. 큐시트 30행은 "디렉터가 수동 '준비→발사'"라고만 적었고 **도구는 미정의.** 클립 파일명이 `01_`~`53_` 번호 체계인 것은 폴더 수동 재생을 암시하는 설계 흔적이다.
- 폴더 수동 재생으로 첫 예식을 치를 수는 있다(번호순 더블클릭). 그러나 그 방식엔 더킹(-6~-18dB 차등)·클립 간 1.5~2.5초 간격·N4~N6 브릿지 즉시 호출·고객 S 자동 로드가 전부 없다. **사고 복구 수단이 가장 필요한 순간에 도구가 가장 허술하다.** 시뮬레이션에서 확인한 위험(오열·덕담)이 전부 "디렉터가 빠르게 다음 수를 꺼내는" 능력에 걸려 있는데, 파일 탐색기에서 mp3를 찾는 3~5초가 그 능력을 잡아먹는다.
- 판정: **콘솔이 첫 예식의 운영 필수품(본체)이고, 고객용 미리듣기는 같은 엔진의 자동 모드 스킨(부산물)이다.** v0.1은 이 주종을 거꾸로 놨었다 — 마케팅 기능을 목적으로, 운영 도구를 시너지로 적었다.
- 폴더 수동 재생은 폐기가 아니라 **플랜 B(백업)로 강등**: 보조 기기에 번호 파일 폴더 상비.

### 역전 2 · 배역 오디오북 사전 제작(구 Phase 1)은 중복 + 리스크

- **중복**: 엔진에 코스 기본 S를 넣으면 '코스 기본형 미리듣기'가 그냥 나온다. 사전 제작 mp3 3종이 그 위에 더하는 것은 배역 음성·믹스 완성도·다운로드 가능성뿐이다.
- **리스크 3개**:
  1. 가짜 신랑·신부 AI 음성의 언캐니 — "전부 AI로 때우는 업체" 인상 위험. 결혼이라는 소재에서 특히 민감.
  2. 실제 상품 구조는 "나레이션만 녹음 · 사람 파트는 사람"인데, 데모가 사람 파트까지 AI로 채우면 **상품 구조를 데모가 거짓말하게 된다.**
  3. 밈 필터(벤더 결정지 §4) 부담이 보이스 4종으로 늘어난다.
- **대안(채택 추천)**: **데모도 실제 구조 그대로.** 나레이션 = 실음성 클립 · 사람 파트 = 텍스트 카드("여기서 두 분의 서약이 이어져요. 직접 소리 내어 읽어보셔도 좋아요"). 이러면 미리듣기 경험 자체가 상품 구조 설명이 된다 — 들리는 것은 당일에도 들리는 것이고, 읽는 것은 당일에 사람이 하는 것이다.
- **사용자 원안("주인공 각각의 음성") 보존**: 폐기가 아니라 **마케팅 제작물(SNS 영상·상담 시연용) 선택지로 이동 · 보류.** 첫 예식 후 니즈를 보고 재검토. → §6 결정 2. **원안 변경이므로 반드시 사용자 결정을 받는다.**

### 부수 발견 · BGM 구독이 '마케팅 준비물'에서 '첫 예식 전제'로 승격

큐시트 §저작권 실측: 상용곡은 **현장 재생만으로도** KOMCA 공연·복제권 대상이다. 콘솔이 당일 BGM을 틀려면(더킹 포함) 라이브러리 구독(Epidemic Sound / Artlist / Musicbed 중 1곳)이 **첫 예식 전에** 결정돼 있어야 한다. 기존 미결 항목의 마감이 앞당겨진 것.

## 2. 새 큰틀: 엔진 하나 · 쓰임 셋

```
[엔진] 클립 시퀀서
  입력: S(코스·옵션·순서) → curSeq() → 클립 목록
  재생: 순서 재생 · 클립 간 간격(1.5~2.5초) · BGM 트랙 + 자동 더킹
  폴백: 오디오 없는 클립은 텍스트 카드 + 무음 → 오디오가 0개여도 전체 작동

[쓰임 A · 본체] 당일 디렉터 콘솔 — 수동 모드 · 첫 예식 전 필수
  - 수동 '다음' 4곳(서약·반지·편지·덕담) = 큰 버튼 하나
  - N4~N6 브릿지(감정 대기·준비 대기·재개) 원터치 — 시뮬레이션 갭 1 해소
  - BGM 더킹 자동(순간별 -6~-18dB 차등 · 큐시트 수치 이관)
  - 고객 S 자동 로드 → 예식마다 큐 프로그래밍 0분
    (QLab류 기성 도구 대신 자체 제작하는 유일한 이유가 이것 — 기성 도구는 예식마다 수동 세팅)

[쓰임 B] 코스 기본형 미리듣기 — 자동 모드 + 코스 기본 S
  - 계약 전 이해·비교. 코스 카드 "이 코스의 하루 읽어보기(듣기)"
[쓰임 C] 커스텀 미리듣기 — 자동 모드 + 고객 ritualDraft.S
  - 완성 직후 "내 예식 미리듣기" · 이미지 트레이닝(집에서 반복 리허설)
  - 가변 구간 카드: "여기서 두 분의 서약이 이어져요. 직접 소리 내어 읽어보셔도 좋아요."
```

콘텐츠 2트랙:

- **트랙 1 · 텍스트 장면 레이어** — 지금 · 0원 · 내 몫. 나레이션 문안은 `ritual-data.js`에서 자동 추출(신규 `scripts/build-course-story.mjs` · `build-dubbing-script.mjs`와 같은 동기 보증 원칙), 지문·장면만 저작. 코스 B·C 집필이 미작성 런북 B·C 초안을 겸한다. 고객판 편집 원칙(내부 용어 제거 · 가상 인물 라벨 · 3~4분 축약 · 오열/덕담 장면은 완곡 포함)은 v0.1 그대로.
- **트랙 2 · 오디오 53클립** — 목소리 A/B 확정 후 제작. **완성되는 대로 클립 단위로 꽂힌다**(전량 완성을 기다릴 필요 없음 · 무음 폴백 덕분).
