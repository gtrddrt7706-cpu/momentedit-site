## 0. 한 줄 결론

**셋 다 성립한다. 단 한 덩어리가 아니라 3단계로 쪼갰을 때만.**

| 단계 | 사용자 제안 원문 | 형태 | 돈 | 시점 |
|---|---|---|---|---|
| **Phase 0** | "코스마다 읽어볼 수 있게 예 부분" | 코스별 예시 대본(텍스트) | 0원 | **지금** |
| **Phase 1** | "진짜 오디오북처럼 주인공 각각의 음성" | 코스 기본형 오디오북 mp3 3종(사전 제작) | 배역 음성 + BGM 구독 | 목소리 A/B 확정 후 |
| **Phase 2** | "커스텀 완성하면 그에 맞춰진 오디오북" | **클립 플레이어**(파일 생성 아님) | 개발만 · 고객당 0원 | 클립 음원 확보 후 |

핵심 통찰이 하나 있다. **커스텀 오디오북은 "파일을 만드는 문제"가 아니라 "재생 순서 문제"다.** 나레이션 53클립은 어차피 한 번만 녹음되는 자산이고, 고객의 커스텀 식순은 그 클립들의 부분집합 + 순서다. 브라우저가 그 순서대로 틀면 그게 곧 맞춤 오디오북이다. 고객마다 TTS를 다시 돌리지도, 서버에서 파일을 렌더링하지도 않는다. **고객당 한계비용 0원.**

## 1. 왜 하는가 (고객 가치)

**코스 선택의 실제 장벽**: 지금 코스는 "입장 → 서약 → 반지 → 선언 → 편지"처럼 순서 이름의 나열로 제시된다. 예비부부는 이 나열로 자기 하루를 그리지 못한다. 장면으로 읽으면 3~4분 만에 그려진다. 시뮬레이션 문서(코스 A 전대본)를 읽어 본 사용자의 즉각 반응("이거 좋다")이 이 가설의 첫 검증이다.

**이미지 트레이닝**: 예비부부의 실제 니즈다. 리허설은 당일 직전 1회뿐인데, 미리듣기는 집에서 반복할 수 있는 리허설 축소판이 된다. 당일 긴장 완화에 직접 기여.

**신뢰 형성**: 이 상품의 최대 불안은 "사회자 없이 괜찮을까"다. ★책임질 수 없는 안심 금지 규칙(2026-07-15)에 따라 문구로 보증할 수 없는 것을, **장면이 근거가 되어 답한다.** 편지를 읽다 목소리가 무너지는 순간 디렉터가 어떻게 곁을 지키는지를 문구가 아니라 장면으로 보여 준다.

**같은 자산의 3차 활용**: ①상담 중 1분 듣기 ②디렉터 신입 교육·리허설 도구 ③(선택) SNS 소재. 단 ③은 §2 포지셔닝 가드를 지킬 때만.

## 2. 포지셔닝 가드 ★필수 준수

CLAUDE.md 나레이션 포지셔닝 규칙(2026-07-16 사용자 지시) verbatim:

> 나레이션은 사회자를 두기 어려운 소규모 예식의 **진행 수단(차선)**이지 상품의 핵심·시그니처가 아니다. 핵심은 '본질에 집중한 마이크로웨딩 + 촬영·예식을 하나로 엮는 기록(140분 시그니처 시퀀스)'. 문구에서 나레이션을 "이끈다·핵심·시그니처"로 띄우지 말고, "진행 안내는 저희가 준비해요 · 사회자 없이도 매끄러워요" 수준의 서포트 프레임으로만 쓴다.

이 기능은 그 규칙과 긴장 관계에 있다. 오디오북을 화려하게 띄우면 나레이션이 도로 시그니처 자리에 앉는다. 그래서:

- **이 기능의 주어는 항상 "예식·하루·코스"다.** "AI 오디오북"을 기능명·카피에 쓰지 않는다.
- 카피 안전 예: "이 코스의 하루를 미리 읽어보세요" / "두 분의 예식, 미리 들어보세요"
- 카피 금지 예: "AI 오디오북이 예식을 이끌어요" / "시그니처 오디오북"
- 고객 노출 문구에 전각 줄표 금지 · 장식 이모지 금지(기존 문구 규칙 그대로).
- 시뮬레이션이 실증했듯 나레이션 실발화는 본식의 **14%**다. 미리듣기도 그 비율을 정직하게 반영한다 — 나레이션 쇼케이스가 아니라 **하루의 흐름** 쇼케이스.

## 3. 3단계 상세

### Phase 0 · 코스별 예시 대본(텍스트) — 지금 · 0원 · 내 몫

원형은 `시뮬레이션_코스A_전대본.md`. **단 그대로 노출하면 안 된다** — 내부 검수 장치(더킹 dB·클립 번호·파일명·디렉터 카드·"사고" 사후분석)가 섞여 있다.

고객판 편집 원칙 5개:

1. **나레이션 문안은 `assets/ritual-data.js`에서 자동 추출.** 지문·대사만 저작 레이어. `build-dubbing-script.mjs`와 같은 원칙("이 대본과 실제 사이트 문안은 항상 같습니다")을 지켜야 문안 개정 때 예시 대본만 낡는 사고가 없다. → 신규 스크립트 `scripts/build-course-story.mjs` 제안: 나레이션(자동) + 장면 레이어(코스별 저작 데이터)를 짜서 고객판 생성.
2. **내부 용어 제거**: 클립 번호·mp3 파일명·dB 수치·큐 표기 → 장면 언어로.
3. **가상 인물 라벨 명시**: "등장하는 두 사람과 가족은 가상의 인물이고, 대사는 예시예요. 실제 예식에서는 두 분이 직접 쓴 글을 읽어요." (고객이 "대사를 정해 주는 건가?" 오해하는 것 차단)
4. **분량**: 코스당 3~4분 읽기(전대본 17분의 축약판). 전개 골격: 입장 → 정점 1(선언) → 정점 2(편지) → 폐식 + 사이는 요약.
5. **오열·덕담 장면 포함(추천·축약)**: '사고'라는 말 없이 "이런 순간도 이렇게 흘러가요"로. 최대 불안에 답하는 신뢰 장치. → §6 결정 3.

부수 효과: **코스 B·C는 시뮬레이션 문서 자체가 없다.** 이번에 쓰면 미작성 상태인 런북 B·C의 초안을 겸한다(원래 내 몫이던 미결을 같이 갚는다).

노출 위치안: (A) 코스 고르기 화면의 코스 카드에 "이 코스의 하루 읽어보기" 접이식/모달 (B) 커스텀 완성 화면에 "내 식순으로 읽어보기" (C) 홈·상담 페이지 링크. **추천 A+B** — 고르기 전(비교)과 고른 후(확인·공유) 두 접점.

### Phase 1 · 코스 기본형 오디오북 3종(사전 제작 mp3) — 목소리 확정 후

- **배역 4보이스**: 성우(확정 보이스) + 신랑 + 신부 + 혼주 1. 배역 보이스도 `벤더_확정_결정지.md` §4 밈 필터를 통과해야 한다("이 목소리 어디서 들어본 것 같아?" 1명이라도 → 탈락). 어머님까지 5보이스는 비용 대비 효과 낮음 → §6 결정 5.
- **지문 낭독은 성우가 겸한다**(오디오북 내레이터). 듣는 사람 입장에선 "지금 들리는 안내 음성이 실제 예식에서 흐르는 목소리"라는 사실 자체가 데모다. 실클립 구간과 지문 구간의 구분은 BGM 변화로(제작 디테일 · Phase 1 착수 때 확정).
- **분량 8~10분 축약판**. 전대본 17분을 그대로 음성화하지 않는다. 특히 덕담 장면은 1분 내로 압축.
- **제작 파이프라인**: 타입캐스트 생성·재생(무료) → 시안 확정 → 다운로드(플랜 분수 소모) → ffmpeg 믹스. 더킹 = `sidechaincompress`(큐시트 수치: 말이 주인공 -15~-18dB · 음악 주인공 -6~-10dB · 페이드 다운 0.3~0.5초/복귀 0.8~1.5초), 라우드니스 = `loudnorm` -16 LUFS. **파이프라인 구축·수치 검증은 내 몫, 최종 청감 검수는 사람**(이 세션은 오디오 재생 불가 · 벤더 결정지 §6).
- **BGM 라이선스가 선행 조건**: 오디오북은 사이트 게시·SNS 재사용까지 가는 배포물이라 라이브러리 구독 1곳(Epidemic Sound / Artlist / Musicbed) 선정이 먼저다(기존 미결 항목 재상정 · 큐시트 §저작권).
- 산출물: 정적 mp3 3개 + 자막 텍스트(= Phase 0 대본 재사용 · 접근성). 코스당 8~10분 × 128kbps ≈ 8~10MB — Vercel 정적 호스팅 무부담.
- **왜 기본형만 사전 제작인가**: 커스텀 조합은 순서 축만 13,632개다. 파일 사전 렌더는 불가능하고, 할 필요도 없다 — 커스텀은 Phase 2가 맡는다.

### Phase 2 · 커스텀 미리듣기 = 클립 플레이어 — 클립 음원 확보 후 · CC 몫

- **파일을 만들지 않는다.** 고객이 커스텀을 완성하면, 그 조합의 클립 목록을 순서대로 재생하는 브라우저 플레이어가 곧 "그에 맞춰진 오디오북"이다. 클립 간 1.5~2.5초 침묵(큐시트 30행)도 재생 간격으로 그대로 재현.
- **데이터 경로는 이미 있다(실측)**: `ritualDraft`가 `S` 전체를 저장한다 — `order-preview.html:1743` `{S:S, summary:{course,count,min,flow}}` → `mypage.html:1430` `p.ritualDraft._v===3 && p.ritualDraft.S`. 플레이어는 저장된 S로 `curSeq()`를 복원해 클립 목록을 얻는다. **새 저장 스키마가 필요 없다.**
- **재생 UI 전례도 이미 있다(실측)**: `order-preview.html:666` `NARR_SAMPLE='/assets/narration/sample-voice.mp3'` — 빌더 안에 샘플 목소리 재생 버튼이 이미 산다. 새 패턴 발명이 아니라 기존 패턴 확장이다.
- **가변 구간(환영·서약·편지·덕담) 처리 2안**:
  - 기본(추천): **지문 카드 + 3초 무음.** "여기서 두 분의 서약이 이어져요. 직접 소리 내어 읽어보셔도 좋아요." ← 이미지 트레이닝의 정점이다. 자기 서약을 자기 목소리로, 자기 예식의 나레이션 사이에서 리허설하게 된다.
  - 토글: Phase 1 더미 대사 음성으로 채워 듣기(예시임을 라벨로 명시).
- ★**같은 엔진 = 현장 재생 콘솔.** 클립 시퀀서는 결국 두 화면에서 쓰인다: ①미리듣기(자동 진행 + 간격) ②당일 디렉터 콘솔(수동 '다음' 4곳 · N4~N6 브릿지 버튼 · BGM 더킹). **엔진 1개에 모드 2개**로 설계하면 두 번 만들지 않는다. 시뮬레이션에서 발견한 N4~N6 배선 없음 갭도 이 콘솔이 갚는다. → CC와 아키텍처 합의 필요(코드 착수는 승인 후).
- **개인정보·감정 원칙(불변)**: 고객의 **실제 서약·편지 텍스트는 절대 TTS 하지 않는다.** ①"당일까지 비밀" 정책과 충돌 ②실물 낭독의 감정 가치를 예식 전에 소진 ③민감 텍스트의 외부 API 전송. 음성은 더미 대사만, 항상 라벨 명시.

### Phase 3 · (보류) 오디오 파일 다운로드 제공

## 5. 비용·순서

| 단계 | 돈 | 작업 | 전제 |
|---|---|---|---|
| Phase 0 | 0원 | 나 · 2~3턴(B 시뮬레이션 → 고객판 A → 생성기 사양) | 없음 · **지금 가능** |
| Phase 1 | 배역 더미 대사 다운로드 분수(코스당 ~8분 × 3 ≈ 24분 · **요금은 계정 화면 실측 필요**) + BGM 구독 1곳 | 나(파이프라인·대본) + 사람 청감 검수 | ★목소리 A/B 확정 · BGM 구독 결정 |
| Phase 2 | 0원(개발만) | CC · 엔진 1개(모드 2개) | 클립 음원 확보 · 아키텍처 합의 |
| Phase 3 | — | 보류 | 첫 예식 후 재검토 |

**순서를 고정하는 이유**: 목소리 확정 전에 Phase 1을 만들면 목소리 교체 시 전량 재작업이다. 즉 이 기획은 새 병목을 만들지 않는다 — **지금의 병목(A/B 목소리 확정)이 그대로 이 기획의 병목이다.** Phase 0만 병목과 무관해서 즉시 착수 가능.
