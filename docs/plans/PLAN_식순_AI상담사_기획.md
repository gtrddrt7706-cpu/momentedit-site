# PLAN · 식순 전문 AI 상담사 기획 (식순 빌더 임베드)

> 2026-07-19 작성. 사용자 요청: "식순안에 들어가는 전문 AI 상담사 — 이벤트 하나하나 모든 걸 파악하고,
> 고객이 진행 중 어떤 질문을 던져도 다 대답할 수 있는 AI 상담사".
> 대상: 식순 빌더(order-preview.html · mypage iframe 오버레이). 기존 AI 상담 인프라(advisor 계열) 위에 얹는다.

---

## 0. 한 줄 컨셉

**"식순을 만드는 그 화면 안에, 이 예식의 모든 순간을 아는 전담 상담사가 함께 앉아 있다."**

- 고객이 빌더를 진행하다 막히는 모든 질문에 즉답: 이벤트의 뜻·유래, 우리 예식에서의 진행 방식, 실제 나레이션 문안, 소요 시간, 누가 무엇을 하는지, 준비물, 예절·관례, "우리 상황엔 뭐가 어울려요?" 같은 추천까지.
- 단순 FAQ봇이 아니라 **지금 이 고객이 만들고 있는 식순(코스·고른 순간·현재 스텝)을 알고** 답하는 그라운딩 상담사.
- 기존 마이페이지 AI(일반 정책·일정·결제)와 역할 분리: 이 상담사는 **예식 순서 전문**. 정책·결제 질문이 오면 아는 범위만 답하고 마이페이지 상담으로 안내.

### 왜 필요한가 (근거)

1. 식순 빌더는 고객이 5~10회 재방문하며 몇 주에 걸쳐 쓰는 도구(상세설계 §0). 그 사이 생기는 질문("링워밍이 뭐예요?", "편지 안 쓰면 이상한가요?", "축가 없으면 허전할까요?")이 지금은 갈 곳이 없다 → 이탈·미완성·불안.
2. 주 고객층은 "주례 없는 소규모 예식"이 처음이라 **관례 지식 자체가 없다**. 연구1~2가 밝힌 근거(감동 이벤트 2개 이내, peak-end, 밸리 배치 등)를 상담사가 풀어주면 선택 불안이 크게 줄어든다.
3. 이벤트별 디테일 질문은 디렉터 상담 시간을 가장 많이 먹는 유형 → AI가 흡수하면 상담은 확정·검수에 집중.

## 2. 지식 설계 (이 기획의 핵심) — `api/_ritual-kb.js` 신설

"이벤트 하나하나 모든 걸 파악"의 실체는 프롬프트가 아니라 **지식베이스의 완성도**다.
3층 구조로 컴파일한다. **단일 진실원 = order-preview.html의 실제 문안·옵션** (빌더 화면과 답변이 1글자도 어긋나면 신뢰 붕괴 · 연구 문서는 '왜'를 채우는 보조 원천).

### 2-1. 이벤트 백과 (1층 · 전 이벤트 × 고정 스키마)

빌더의 모든 스텝/순간을 같은 틀로 기술. 대상: 하객 맞이 · 입장(멘트 A~F) · 베일다운 · 첫인사(환영) ·
혼인 서약 · 링워밍 · 반지 교환 · 성혼 선언(낭독 주체 3종) · 밸리(와인·유니티/케이크/비움) · 축배 ·
축가 · 편지 낭독(대상 3종·성우 대리) · 부모님 헌정 · 부모님 덕담 · 성장영상 · 글 적기 · 폐식·단체촬영.

각 이벤트당 항목(스키마):

```
① 정의·유래        이게 뭔지, 어디서 온 관례인지 (예: 베일다운=일본 표준·한국 희귀)
② 우리 진행 방식    모먼트에디트에서 실제로 어떻게 흘러가는지(앞뒤 연결 포함)
③ 나레이션 문안     빌더에 있는 실제 멘트 전문(버전별 A/B/C…) — 화면과 동일 인용
④ 소요 시간        분 단위 + 총 시간(약 25~30분) 안에서의 비중
⑤ 선택지·스왑      고객이 고를 수 있는 옵션 전부와 각각의 느낌 차이
⑥ 사람·역할        누가 하는지(신랑·신부/부모님/지인/성우), 섭외·부탁 팁
⑦ 준비물·마감      뭘 준비하는지, D-7(글·파일)·D-14(식순 확정) 기한
⑧ 자주 묻는 질문    "안 하면 이상한가요?" "오열할까 봐 걱정돼요"(→성우 대리) 등 예상 Q&A
⑨ 추천 근거        연구 기반 한 줄(감정 아크·어른 하객·소규모 특성) — 왜 이 코스에 이 순서인지
⑩ 미정·상담 항목    이 이벤트에서 아직 확정 안 된 것(→ 답 안 만들고 상담 안내)
```

### 2-2. 구조·코스 지식 (2층)

- 코스 A 담백 / B 감동 / C 가족: 배열·감정 아크·스왑 슬롯·누구에게 어울리는지 (코스설계_v1).
- 공통 설계 규칙: 자물쇠 3(입장·첫인사·폐식) · 감동 이벤트 2개 이내 · 밸리 배치 · 정점 65~85% · 끝은 정돈된 벅참 → 단체촬영.
- 시간 구조: 본식 약 25~30분, 140분 시퀀스 안에서의 위치(준비→스냅→본식→단체 기록→배웅).
- "0개 더해도 완성"(담백함이 기본) · 특별 요청(목록 밖)=셀프 아님·상담 경로.

### 2-3. 운영 정책 (3층 · 기존 `_kb.js`에서 발췌 + facts 주입)

- 수정 기한(식순 확정 D-14 · 화면 표기와 통일 — 결정 대기함의 D-9/D-14 건 확정 시 이 값 하나만 교체),
  글·음성 파일 D-7 전달, 성장영상 링크 제출, 외부 음원·축가 범위(미정이면 상담), 종교 의식·반려동물(기존 KB 값),
  사회자 예외 경로, 시간 연장(미정 → 상담).
- **미정 목록**: `PLAN_AI상담사_결정필요.md` A절(리허설·지연 대응·연장 비용 등) 그대로 계승 — 답을 만들지 않고 상담 연결.

### 2-4. KB 정합 유지 장치

- KB 파일 상단에 원천 명시: "빌더 문안 변경 시 이 파일 동시 갱신" 주석 + `점검` 스킬 점검 항목에 "빌더 문안 ↔ 식순 KB 대조" 추가.
- 가격·기한처럼 움직이는 값은 KB에 하드코딩하지 않고 **aiFacts(핵심정보) 우선** 규칙으로 덮어쓰기(기존 advisor와 동일한 [운영 핵심정보 최우선] 블록).

## 3. 그라운딩 — "지금 두 분의 식순"을 알고 답한다

빌더의 상태 `S`를 요약 문자열로 만들어 요청에 동봉(기존 마이페이지 `state` 그라운딩과 동일 패턴·격리 블록 재사용):

```
[지금 만드는 식순]
코스: 담백 · 현재 화면: 편지 낭독
고른 순서: 입장(멘트 A·서사형) → 첫인사(직접) → 서약(직접) → 반지 O → 성혼(성우) → 밸리 없음 → 편지(부모님께) → 폐식
추가한 순간: 축가(가족) · 뺀 것: 덕담
시간 합: 약 26분 · 서약문: 작성됨(310자) · 편지: 아직 비어 있음
예식일: 2026-10-24 (D-97) · 신랑 OOO · 신부 OOO
```

- 이걸로 가능한 답: "지금 구성이면 몇 분이에요?", "우리 식순에서 편지 다음이 뭐죠?", "축가를 빼면 허전할까요?"(현재 배열 기준 추천), "제가 뭘 아직 안 채웠죠?".
- **비밀 보호(절대 규칙)**: 서약문·편지·인사말 **본문은 전송하지 않는다**. 글자수·작성 여부만 보낸다.
  ("내용은 당일까지 비밀로" 프레임과 일치 · AI에게도 안 보여준다고 안내 가능 — 프라이버시가 셀링 포인트가 됨.)
- 임베드(mypage) 모드: 이름·예식일·D-day는 mypage가 이미 가진 base 데이터에서 주입. 독립 열람(시안 보기) 모드: 상태 요약 없이 KB만으로 동작(이름 미치환·일반 답변).

## 4. UI — 빌더 안에서, 스텝을 아는 상담사

### 4-1. 진입

- **공용 위젯 재사용**: order-preview.html에 `advisor-widget.js` 로드, `ME_ADV_PAGE={page:'식순',...}`.
  FAB 위치·드로어 UX는 기존과 동일(학습 비용 0). 임베드 모드에서도 iframe 내부에 그대로 뜬다.
- 인사말: `식순을 만들다 궁금한 건 뭐든 물어보세요. 순서 하나하나의 진행 방식과 문안을 알고 있어요.`
  (★나레이션 포지셔닝 규칙 준수 — "나레이션이 이끈다" 류 문구 금지.)

### 4-2. 맥락 칩 (차별 포인트)

- 드로어를 열면 **지금 보고 있는 스텝에 맞는 추천 질문 칩** 3개가 먼저 보인다.
  - 편지 스텝: `편지는 보통 얼마나 길게 쓰나요?` `읽다가 울 것 같으면 어떻게 하나요?` `부모님께와 서로에게, 뭐가 다른가요?`
  - 링워밍 스텝: `링워밍이 뭔가요?` `가족만 돌리면 몇 분 걸리나요?` `반지 교환과 같이 해도 되나요?`
  - 코스 스텝: `담백과 감동, 뭐가 다른가요?` `저희는 어른 하객이 많은데 어떤 코스가 맞을까요?`
- 구현: 위젯 CFG에 `chips: function(){ return RITUAL_CHIPS[현재 스텝 k] }` 형태(스텝 전환 시 갱신). 칩 답변도 동일 엔드포인트로(즉답 하드코딩 아님 — 상태 그라운딩이 섞여야 해서).

### 4-3. 톤

- 마이페이지 전담 비서 페르소나 계승(영업 0 · 계약 고객 케어). 답변 2~5문장 · 존댓말 · 마크다운/전각 줄표 금지(기존 규칙 동일).
- **책임질 수 없는 안심 금지** 규칙을 시스템 프롬프트에 명문화: 안심 문장엔 반드시 근거(누가·무엇으로)를 붙인다.

## 5. 시스템 프롬프트 골격 (`api/ritual-advisor.js`)

advisor.js의 [엄격한 규칙] 1~9 계승 + 식순 전용 추가:

```
10. 당신의 전문 분야는 예식 순서(식순)입니다. 이벤트의 뜻·진행·문안·시간·준비물·추천은 끝까지 답합니다.
11. 나레이션은 진행을 돕는 수단으로만 말합니다. "나레이션이 예식을 이끈다·핵심·시그니처" 식 표현 금지.
12. 화면에 없는 새 이벤트·연출을 즉석에서 약속하지 않습니다. 목록 밖 특별 요청은 "디렉터와 상담에서 함께
    설계해요"로 안내합니다(가능·불가능을 단정하지 않음).
13. 고객이 쓴 서약·편지 본문은 당신에게 제공되지 않습니다. 내용 첨삭 요청엔 일반 작성 팁(길이·구조·마무리
    문장)으로 돕고, 본문은 당일까지 비밀로 간직하도록 권합니다.
14. 안심 문구엔 반드시 근거를 붙입니다. 시간 자랑·포괄 보증("다 해드려요") 금지.
15. 가격·결제·계약·일정 변경 등 식순 밖 개인 업무는 아는 일반 정책만 짧게 답하고 마이페이지 상담으로 안내합니다.
```

- 모델: `claude-sonnet-4-6` · thinking disabled · effort low (기존 접점과 통일).
- 캐싱: KB+규칙 블록 `cache_control: ephemeral` (기존과 동일 → 재질문 시 ~90% 절감). 상태 요약은 비캐시 블록.
- 가드: `_ratelimit` 동일 기준 · MAX_STATE_LEN은 식순 요약이 길어 2600자로 상향.
- 토큰: MAX_TOKENS 700 유지. 예상 비용: KB 약 15~20k 토큰 → 캐시 후 질문 1건당 대략 10~25원(접점 '식순'으로 💰 패널에서 실측 확인).

## 6. 에스컬레이션·운영 루프

- 못 푸는 질문 → `[[ESCALATE]]` → 기존 인계 박스 → `api/handoff.js`(접점 '식순') → 관리자 메일+대기 큐. **기존 아침보고·미처리 인계 집계에 자동 포함**(GAS 무변경).
- `_qlog` 적재로 💡개선 탭에 식순 질문이 쌓임 → 자주 막히는 질문은 ①KB 보강 ②`aiFactSet` 핵심정보 ③`PLAN_AI상담사_결정필요.md` A절에 답 채우기로 승격.
- 회귀셋(aiReg)에 식순 대표 질문 5~8개 등록(예: "링워밍이 뭐예요" "편지 대신 성우가 읽어줄 수 있나요" "총 몇 분이에요" "축가 꼭 있어야 하나요") → 매일 안전점검이 품질 감시.
- `scripts/ai-live-sim-ci.js`(라이브 시뮬레이션)에 식순 접점 시나리오 추가 검토(Phase 2).

## 7. 단계별 실행

| Phase | 내용 | 파일 | 배포 |
|---|---|---|---|
| **0. KB 컴파일** | 빌더 전 문안·옵션 추출 → 이벤트 백과(§2-1 스키마 전 이벤트) + 코스·정책층 작성. 빌더와 전수 대조 | `api/_ritual-kb.js` | 코드만(엔드포인트 없음) |
| **1. 상담사 출시** | 엔드포인트(프롬프트·가드·로그·인계) + 위젯 연결 + 맥락 칩 + 상태 요약 그라운딩(비밀 글 제외) | `api/ritual-advisor.js` · `order-preview.html` | Vercel 자동 · **GAS 무변경** |
| **2. 운영 심화** | 회귀셋 등록 · 라이브 시뮬 시나리오 · 질문 로그 기반 KB 보강 사이클 · 감동/가족 코스 확정분 KB 반영 | KB·GAS 회귀셋(관리자 화면에서) | 수시 |
| **3. 행동 연결(검토)** | AI 답변에서 실제 빌더 조작 제안 버튼("케이크로 바꿔볼까요? → [바꾸기]") — postMessage로 S 반영 | 별도 기획 | 결정 대기함 |

- 순서 의존: Phase 0~1은 **지금 빌더(담백 코스) 기준으로 바로 가능**. 감동·가족 코스 멘트가 확정되면 KB에 증분 반영(구조가 스키마라 추가 쉬움).
- 식순 빌더의 mypage 실이식(실행플랜 C-2)과 독립 — order-preview에 붙이므로 이식 전에도 임베드·독립 모두 동작.

## 8. 결정 대기함 (추천값으로 진행 · 몰아서 질문)

1. **AI의 빌더 직접 조작(Phase 3) 도입 여부** — 추천: **보류**. 답변→고객이 직접 탭이 안전(오조작·"AI가 맘대로 바꿈" 리스크). 질문 로그에서 "바꿔줘" 수요가 실제로 보이면 재검토.
2. **위젯 노출 범위** — 추천: **임베드(계약 고객)와 독립 열람 모두 노출**. 독립 열람(시안 구경) 단계의 질문은 전환을 돕는 실질 상담이고, 비용 가드는 기존 레이트리밋으로 충분.
3. **서약·편지 첨삭 기능** — 추천: **본문 비전송 유지**(§3). 첨삭이 필요하면 "AI에게 보여주고 다듬기"를 고객이 명시적으로 켜는 옵트인으로 별도 기획(비밀 프레임과 충돌하므로 신중).
4. (기존 항목 재확인) **식순 수정 마감 D-9 vs D-14 통일** — 이 상담사의 KB에 박히는 값이라 Phase 1 전 확정이 좋음. 추천은 기존 항목대로 D-9.
