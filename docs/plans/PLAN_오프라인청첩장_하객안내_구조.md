# 기획안 · 오프라인 청첩장 ↔ 하객 안내 구조 (확정본)

작성: 2026-07-17 · 상태: **핵심 적용 완료** (마지막 섹션에 잔여 항목)
근거 대화: 사장님 3원질문(구조·노출·마이페이지) → 개선 제안(A~D) → 확정.

## 1. 배경과 문제

좌석 배치도·애프터 웨딩의 **결과물이 오프라인 청첩장에 반영**되어야 한다.
그런데 이 둘의 확정 시점(좌석 D-9)과 청첩장 전달 시점(D-30~60)이 어긋난다.
"청첩장이 완성되려면 좌석·애프터가 끝나야 하나?"가 출발 질문.

## 2. 확정 원칙 3가지

### 원칙 1 · 제작 구조는 분리 유지 (흡수하지 않는다)
청첩장·식순·애프터 웨딩·최종 확정·좌석 배치도는 **각자 트랙**으로 진행.
청첩장 파트에 흡수하면 비대해진다는 판단(사장님) 그대로.
결과물만 하객 안내 페이지(guide.html)로 **자동 합류**한다.

### 원칙 2 · 청첩장에는 링크만, 내용은 라이브 페이지가 담당 (링크 원칙)
청첩장(오프라인·종이)에 좌석·식사 내용을 직접 싣지 않는다.
- 미관: 전부 실으면 지저분함 (사장님)
- 시간: 좌석 확정(D-9)은 청첩장 인쇄(D-30~60)보다 늦어 **내용 인쇄가 애초에 불가능**
- 결론: 청첩장에는 **고정 링크(QR)** 만. 링크가 가리키는 안내 페이지가 나중에 채워진다.
- 효과: **의존성이 풀린다.** 청첩장은 좌석·애프터와 무관하게 먼저 완성 가능.

### 원칙 3 · 잠금 없이 부분 노출 (비워두고 자동 반영)
"좌석·애프터 완료 전엔 청첩장 미완성" 같은 잠금은 두지 않는다.
- 하객 안내 페이지는 **준비된 섹션만** 노출 (빈 섹션은 하객에게 안 보임)
- 채워지는 즉시 같은 링크에서 자동 반영
- 신랑신부는 마이페이지에서 **부분 노출 현황 칩**과 "하객 눈으로 미리보기"로 실시간 확인

## 3. 구성 요소 지도

```
[마이페이지 제작 트랙]                    [하객이 보는 것]
청첩장(온라인·직접 모시는) ─────────────→ 청첩장 페이지 (완성 화면에 안내 링크 동반)
애프터 웨딩(다이닝) ──┐
좌석 배치도 ──────────┼─ 자동 합류 ────→ 하객 안내 페이지 guide.html?g=토큰
안내 설정(토글 2개) ──┘                    · 내 자리 찾기(이름 검색·토글로 온오프)
                                           · 식사·애프터
                                           · 라이브 중계(토글·청첩장 발행 시)
                                           · 당일 배너(예식일에만)
```

- 토큰 발급: 내용 있는 다이닝/좌석 완료 시 서버(GAS)가 발급 · 예식 +30일 후 링크 닫힘
- 오프라인 활용: 마이페이지에서 **QR 저장·링크 복사** 제공. 종이 청첩장·인쇄물에
  신랑신부가 **알아서** 활용 (별도 동봉 카드 PDF는 만들지 않기로 · 사장님 지시)

## 4. 하객 안내 페이지 구성 (확정)

| 순서 | 섹션 | 노출 조건 |
|---|---|---|
| 배너 | "오늘 두 분의 예식일이에요" | 예식 당일에만 |
| 1 | 내 자리 찾기 (이름 검색) | 좌석 배치 완료 + 이름 입력됨 + 토글 ON |
| 2 | 식사 · 애프터 | 다이닝 확정 시 |
| 3 | 라이브 중계 | 토글 ON + 청첩장 발행 시 |

### 폐기한 섹션과 이유 (2026-07-17 사장님 지시)
- **오시는 길**: 외부 예식장을 가정한 일반형 설계의 잔재. 모먼트에디트는 자체 홀
  고정이라 고객이 식장 주소를 입력할 이유가 없음. 식장 안내는 청첩장이 담당.
- **드레스코드**: 어른들을 모시는 자리에 복장 지정은 예우에 어긋남.
- 이에 따라 마이페이지 "하객 안내 정보" 입력 6칸 → **"하객 안내 설정"** 토글 2개
  (자리 찾기 허용 · 라이브 노출)로 축소.
