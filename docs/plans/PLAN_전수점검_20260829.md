## [MAIN_LANDMARK] 짝 없는 `</div>` 하나가 본문을 반으로 갈라 놓고 있었다 — 2026-09-06

`index.html` 에 **닫을 것이 없는 `</div>`** 가 하나 있었다. HTML 파서는 `</div>` 를 만나면
«div 를 하나 꺼낼 때까지» 스택을 뽑는데, 그 자리에 남은 div 가 없어 **`<main>` 을 대신 닫았다.**

### 무엇이 어긋났고, 무엇은 멀쩡했나
- ✗ 다섯 섹션이 **본문 랜드마크 밖** — 랜드마크로 훑는 사람에게 홈이 반쪽이었다.
  같은 날 넣은 건너뛰기 링크(`#main`)가 가리키는 «본문»도 가격 앞에서 끝나 있었다.
- ✗ `#live` 섹션 박스가 제 내용을 안 담았다 — 박스 1,512px / 내용 3,564px.
- ○ **화면은 멀쩡했다.** 문서 높이 차이 24,652 → 24,709 로 **57px**. 섹션 사이 여백이 제자리를
  찾은 것이라 리듬은 오히려 살았다. nav 앵커는 섹션의 «위쪽»을 쓰므로 영향 없음.
- ★중간에 «빈 화면 2,000px» 로 읽고 그렇게 보고했는데 **틀렸다.** 그건 **스크롤 전** 상태의
  섹션 박스 간격이었다. 끝까지 훑고 다시 재니 빈 화면이 아니었다.

## ★[PUSH_HEAD] 내가 낸 푸시 사고 — 빈 PR 로 병합됐다 (2026-09-06)

`git checkout -B main origin/main` 으로 **main 위에 서 있는 채** 작업하고 커밋한 뒤,
`git push -u origin claude/...` 로 **다른(오래된) 브랜치 이름**을 밀었다.
그 브랜치는 이미 병합된 커밋을 가리키고 있어서 푸시가 사실상 아무것도 안 올렸고,
그 위에 만든 PR #660 은 **파일 0개**로 병합됐다(`120dc02e` — 제목만 남고 내용 없음).
다음 턴에 `git checkout -B main origin/main` 을 또 해서 **로컬 커밋까지 지워졌다.**

- 겉으로는 전부 초록이었다 — 커밋도, 푸시도, CI 도, 병합도 성공 메시지를 냈다.
- 들킨 계기는 다음 작업에서 `grep -c MAIN_LANDMARK index.html` 이 **0** 이 나온 것뿐이다.

**규칙**: 작업 브랜치에 **먼저 서고**(`git checkout -B <branch>`), 밀 때는 **HEAD 를 명시**한다 —
`git push --force-with-lease -u origin HEAD:<branch>`. 그리고 병합 뒤에는
`git show --pretty=format: --name-only <merge sha>` 로 **파일 목록이 비지 않았는지** 확인한다.
