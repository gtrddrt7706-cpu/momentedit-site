## 2. 남은 것 — 우측 아이콘 레일과 본문 글자의 겹침

**레일(`.me-fab-stack`)은 의도된 설계다. 없애지 말 것.** 문제는 본문이 자리를 안 비켜주는 것이다.

### 2-1. 측정 방법 (그대로 재현할 것)
- `Range.getClientRects()` 로 **실제 그려진 줄 사각형**을 쓴다.
  `element.getBoundingClientRect()` 는 줄바꿈된 블록의 전체 상자를 주므로 부정확하다.
- 한 스크롤 지점만 재지 말 것 — **문서 전체를 700px 씩 훑어야** 최악값이 나온다.
  (한 지점만 재면 «그 자리에 긴 줄이 없어서» 0 이 나온다. 실제로 그렇게 속았다.)
- 겹침 = 글자 줄 사각형과 **아이콘** 사각형의 가로 교집합(세로도 겹칠 때만).

### 2-3. ★사용자가 준 수치와 다르다 — 내 값을 쓴다
사용자 메모는 320px 에서 「글자끝 285 · 17px 침범」이었으나, 같은 폭에서 **최대 35.2px** 이 나왔다.
사용자 값은 한 스크롤 지점(8000)의 특정 문장만 본 것이고, 문서 전체로는 더 크다.
또 사용자가 지목한 문장들(「마지막엔 다 함께…」 등)은 **최악이 아니다** — 최악은 히어로 워드마크다.

### 2-4. ★사용자 전제 하나가 틀렸다 — 이건 잠복이 아니라 «지금 나는» 결함이다
사용자 메모: *"지금은 그 자리에 링크가 없어 드러나지 않는다."* → **아니다.**

| 페이지 | 폭 | 겹친 링크·버튼 | 레일이 클릭을 가로챈 수 |
|---|---|---|---|
| `index.html` | 320px | 22건 | **22건 전부** |
| `index.html` | 390px | 12건 | **12건 전부** |

가로채는 실제 링크 예: **「청첩장 미리보기 →」**(y≈12514) · **「진행 현황 화면 보기」**(y≈18759) ·
갤러리 셀 `Wedding moment 03 on Instagram`(y≈5432).
`elementFromPoint` 로 확인했다 — 그 좌표의 클릭은 **레일이 받는다.**

### 2-5. 왜 폭을 넓혀도 안 없어지나 (구조)
```
레일 좌표   = W − right − 46        (모바일 right:6px · 데스크톱 22px · 아이콘 폭 46px)
본문 우한계 = W − padding           (모바일 20px · ≥769px 28px)   ※ W < 876 일 때
            = (W + 820) / 2                                        ※ W ≥ 876 (--max:820 가운데 정렬)
```
둘 다 화면폭을 따라 함께 움직이므로 **좁은 폭에서는 겹침이 상수(모바일 32px)** 다.
`--max: 820px` 이 걸리는 지점부터만 벌어진다.
- **구조적 안전 경계 = 956px** — `(W+820)/2 ≤ W−68` 을 푼 값. 이 위로는 «원리상» 안 겹친다.
- **실측 안전 경계 = 890px** — 지금 문구 기준. ★**문구가 길어지면 890 은 올라간다.** 믿지 말 것.

### 2-6. 레일의 성질 (사용자 메모대로 확인됨)
- `position: fixed · right: 22px(모바일 6px) · top: 50% · z-index: 95`
- 아이콘 6개 · 각 46px · 컨테이너 46×336
- `background: rgba(0,0,0,0)` · `backdrop-filter: none` → **아이콘 획과 글자 획이 같은 자리에 겹쳐 그려진다**
- `pointer-events: auto` → §2-4 의 클릭 가로챔

### 2-7. 파급 범위 — `index.html` 하나뿐이다
| 페이지 | 레일 | 겹침 |
|---|---|---|
| `index.html` | 아이콘 **6개** 표시됨 | 320px 116줄 · 390px 72줄 |

| `schedule.html` | 아이콘 **1개**만 표시(46×46) | 0 (지금 문구 기준) |

CSS 정의는 `index.html:7839`(2026-09-06 기준 · **행번호 말고 `.me-fab-stack` 로 찾을 것**),
위젯 자체는 공용 `assets/advisor-widget.js`. **고치면 세 페이지에 함께 간다.**

### 2-8. #666 과 다른 건이다
#666 은 **280px 가로 스크롤**(문서가 화면보다 넓어짐)을 고쳤다.
이건 **세로로 떠 있는 레일과 글자의 충돌**이라 가로넘침은 0인 채로 발생한다. 서로 무관하다.
