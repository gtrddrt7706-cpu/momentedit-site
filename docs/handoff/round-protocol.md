# 왕복 작업 규칙 — 코워크 ↔ 코드

작성 2026-09-06. 기준 커밋 `4b49b977`.

---

## 1. 왜 이 규칙이 필요한가

`/점검` 라운드에서 **붉었던 4건 중 3건이 «재는 쪽» 문제**였다(#665).
같은 기간 코워크가 낸 3건 중에도 **2건이 오탐**이었다.

- 히어로 로고 대비 `1.09:1` — **페이드인 중간**을 잰 값이었다
- 「빈 화면이 연속된다」 — **리빌 대기가 1.2초로 짧았다**

양쪽 타율이 **똑같이 3분의 1**이다. 한쪽이 더 정확해서 왕복하는 게 아니다.

> **그래서 왕복의 목적은 발견을 늘리는 것이 아니라 헛발을 걸러내는 것이다.**

발견 하나를 더 찾는 것보다, 이미 올라온 발견이 진짜인지 가려내는 편이 값이 크다.
헛발은 조용히 사라지지 않는다 — 고치는 손이 실제 화면을 망가뜨린다.

---

## 2. 역할

| | 할 수 있는 것 |
|---|---|
| **코드만** | 저장소 읽기·수정 · `push` · `merge-guard` · 배포 · git 이력 조회 · GAS |
| **코워크만** | 사용자가 올린 이미지 읽기 · 인스타 릴스 영상 · 웹 문서와 GitHub 조회 · 독립 클론으로 반증<br>★외부 웹사이트 렌더는 **불가**(차단됨) |
| **겹침** | **렌더 측정 — 일부러 둘 다 잰다.** 이게 이 규칙의 핵심이다 |

겹치는 일을 일부러 중복시키는 이유는 §1 이다. 두 값이 갈리는 순간이 헛발을 잡는 자리다.

## 3. 발견을 올리는 형식

```
발견 ·      (한 줄)
잰 값 ·     (숫자. 조건 명시 — 폭 · 스크롤 위치 · 대기시간)
잰 방법 ·   (어떤 API 로 어떻게 · 무엇을 기준선으로 삼았는지)
기준 커밋 · (어느 커밋에서 쟀는가)
반대편 확인 · 일치 / 불일치 / 미확인
```

★「잰 방법」에 **무엇을 기준선으로 삼았는지**를 반드시 적는다.
같은 화면을 봐도 기준선이 다르면 값이 갈린다 — §6 이 실제 사례다.

## 4. 판정

| 상태 | 하는 일 |
|---|---|
| **양쪽 일치** | 진짜다. 고칠 안을 만든다 |
| **양쪽 불일치** | **먼저 «재는 쪽»을 의심한다.** 제품을 고치기 전에 측정 조건 차이(대기시간·뷰포트·커밋·기준선)부터 대조한다 |
| **한쪽만 쟀다** | **«미확인»으로 두고 반대편에 넘긴다. 고치지 않는다** |

불일치일 때 제품부터 고치면, 실제로는 멀쩡한 화면을 «고쳐서» 망가뜨린다.
지금까지 그렇게 될 뻔한 것이 5건이다(§1 의 3건 + 코워크 2건).

## 5. 측정할 때 지켜야 할 것 — 지금까지 걸린 함정들

1. **리빌 애니메이션은 최소 2초 기다린 뒤에 잰다.**
   1.2초로 쟀다가 「빈 화면 연속」 오탐이 났다.
2. **글자 겹침은 `Range.getClientRects()` 로 잰다.**
   `element.getBoundingClientRect()` 는 줄바꿈된 블록의 **전체 상자**라 실제 글자와 다르다.
3. **대비는 화면에 그려진 색을 재고, 애니메이션이 끝난 뒤에 잰다.**
   페이드인 중간을 재서 `1.09:1` 오탐이 났다.
4. **헤드리스와 실기기는 다르게 보인다.** 미묘한 톤은 실기기 확인 전에 확정하지 않는다
   (히어로 진사→크림 구간이 실제로 그랬다).
5. **잰 커밋을 항상 적는다.** 상대가 다른 커밋을 보고 있을 수 있다.
6. **★한 스크롤 지점만 재지 않는다.** 문서 전체를 훑어야 최악값이 나온다.
   한 지점만 재면 «그 자리에 긴 줄이 없어서» **0 이 나온다** — 실제로 880·900px 에서 그렇게 속았다.
7. **★무엇을 기준선으로 삼았는지 적는다.** 아이콘의 **버튼 상자**와 **실제 획**은 12.5px 떨어져 있다.
   기준이 다르면 같은 화면에서 27px 과 15px 이 동시에 나온다(§6).
8. **★자동 생성 파일을 손으로 고치지 않는다.** `audio-review-tone.html` 을 손편집했다가
   게이트에 걸렸다. 생성기와 **짝으로** 고쳐야 한다.

## 6. 지금 미해결로 넘어온 것 — 레일과 본문 글자의 겹침

### 6-1. 사안
320px 폭에서 우측 아이콘 레일(`.me-fab-stack`)과 본문 글자가 겹친다.
**레일은 의도된 설계다. 없애지 말 것.** 본문이 자리를 안 비켜주는 것이 문제다.

### 6-2. 코워크가 올린 값
> 커밋 `4b49b977` · 320px · scrollY 8000 · Range 기준
> - 「마지막엔 다 함께 모여 단체사진을…」 글자끝 285 · 아이콘 268 · **17px**
> - 「두 분의 기획이 실현되는 순간…」 글자끝 293 · 아이콘 **281** · **12px**
> - 「두 분이 자리마다 찾아가 인사를…」 글자끝 277 · 아이콘 268 · **9px**
> - 「인사 사진」 글자끝 275 · 아이콘 268 · **7px**

### 6-3. 코드가 같은 조건으로 다시 잼 — **판정: 일치(기준을 맞추면)**
`index.html` 이 `4b49b977` 과 **바이트 동일**함을 확인한 뒤, 320px · scrollY 8000 ·
`Range.getClientRects()` · 리빌 대기 2.5초로 다시 쟀다.

**차이의 원인은 «기준선»이었다.**

```
레일 268 ~ 314 (46px 버튼)
  버튼 상자 좌 = 268        ← 누르는 영역
  아이콘 획 좌 = 280.5      ← 눈에 보이는 획 (버튼 안쪽으로 12.5px)
```

코워크 목록은 두 기준을 **한 목록에 섞어** 적었다(268 과 281 이 함께 있다).
기준을 맞추면 값이 붙는다:

| 문장 | 코워크 | 코드(획 기준) | 코드(상자 기준) |
|---|---|---|---|
| 두 분의 기획이 실현되는 순간… | 12px | **14.8px** | 27.3px |
| 두 분이 자리마다 찾아가 인사를… | 9px | 12.8px | 25.3px |
| 마지막엔 다 함께 모여 단체사진을… | 17px | −5.8px(안 겹침) | 6.7px |
| 인사 사진 | 7px | (이 스캔에 안 잡힘) | — |

앞 두 문장은 **획 기준으로 일치**한다. 뒤 두 문장은 글자끝 값 자체가 달라
(285 vs 274.7 / 275 vs 미검출) **미확인**으로 남긴다 — 같은 문단이 여러 줄로 쪼개지므로
서로 다른 줄을 골랐을 가능성이 크다.

**두 기준 모두 «겹친다»는 결론은 같다.** 그래서 판정은 «일치»다.

### 6-4. 문서 전체를 훑은 값 (한 지점이 아니라 전 구간)

| 폭 | 버튼 상자 기준(클릭) | | 아이콘 획 기준(시각) | |
|---|---|---|---|---|
| | 최대 | 겹친 줄 | 최대 | 겹친 줄 |
| 320px | **32.0px** | 118 | **19.5px** | 41 |
| 390px | **30.7px** | 72 | **18.2px** | 15 |

★**최악은 본문이 아니라 히어로 워드마크 `MOMENT EDIT`(y≈389)** 다 — 320px 에서 35.2px.

### 6-5. ★코워크 메모 한 줄은 사실과 다르다
> *"지금은 그 자리에 링크가 없어 드러나지 않는다."*

**아니다.** `elementFromPoint` 로 확인했다.

| 폭 | 레일과 겹친 링크·버튼 | 레일이 클릭을 가로챈 수 |
|---|---|---|
| 320px | 22건 | **22건 전부** |
| 390px | 12건 | **12건 전부** |

실제로 가로채지는 링크: **「청첩장 미리보기 →」**(y≈12514) ·
**「진행 현황 화면 보기」**(y≈18759) · 갤러리 셀 `Wedding moment 03 on Instagram`(y≈5432).

**잠복 위험이 아니라 지금 나고 있는 결함이다.**

### 6-6. 레일의 성질 (코워크 메모대로 확인됨)
- `position: fixed` · `right: 22px`(모바일 `6px`) · `top: 50%` · `z-index: 95`
- 아이콘 6개 · 버튼 46px · 획 21px · 컨테이너 46×336
- `background: rgba(0,0,0,0)` · `backdrop-filter: none` → 획과 글자가 같은 자리에 겹쳐 그려진다
- `pointer-events: auto` → §6-5 의 클릭 가로챔

### 6-7. 왜 폭을 넓혀도 안 없어지나
```
레일 좌     = W − right − 46
본문 우한계 = W − padding            (W < 876)
            = (W + 820) / 2          (W ≥ 876 · --max:820 가운데 정렬)
```
둘 다 화면폭을 따라 함께 움직여 **좁은 폭에서는 겹침이 상수(모바일 32px)** 다.
- **구조적 안전 경계 = 956px** — 원리상 안 겹치는 지점
- **실측 안전 경계 = 890px** — ★지금 문구 기준. **문구가 길어지면 올라간다. 믿지 말 것**

### 6-8. 파급 범위 — `index.html` 하나뿐
| 페이지 | 레일 상태 | 겹침 |
|---|---|---|
| `index.html` | 아이콘 6개 표시 | 320px 118줄 · 390px 72줄 |
| `mypage.html` | **`display:none`** | 0 |
| `schedule.html` | 아이콘 1개만(46×46) | 0 (지금 문구 기준) |

CSS 는 `index.html` 의 `.me-fab-stack`(행번호로 찾지 말 것), 위젯은 공용 `assets/advisor-widget.js`.
**고치면 세 페이지에 함께 간다.**

### 6-9. #666 과 다른 건이다
#666 은 **280px 가로 스크롤**(문서가 화면보다 넓어짐)을 고쳤다.
이건 **세로로 떠 있는 레일과 글자의 충돌**이라 가로넘침 0 인 채로 발생한다. 서로 무관하다.

## 7. 선택지 — 레일 유지 전제 (사용자가 고른 뒤에만 수정)

| | 무엇을 바꾸나 | 무엇이 달라지나 | 세 페이지 영향 | 되돌리기 |
|---|---|---|---|---|
| **A. 본문이 비켜준다** | `section` 의 오른쪽 여백을 레일 폭만큼 늘린다(모바일 20 → 약 72px) | **시각·클릭 둘 다 해결.** 대신 320px 본문 폭이 280 → 248px 로 **11% 줄어** 줄당 글자 수가 감소한다. `momentedit-design` 「본문 65~75자」 규칙과 대조 필요 | `index` 만 눈에 띄게 바뀜(나머지 둘은 겹침이 없어 무변화). 단 `section` 규칙이라 전 섹션에 걸린다 | 싸다(CSS 한 값) |
| **B. 레일이 비켜준다** | 기존 `[FAQ_DODGE]` 방식을 확장 — 겹치는 동안만 레일이 물러나거나 흐려진다 | **본문 폭 무변경**(브랜드 리듬 보존). 대신 스크롤마다 겹침 계산이 한 곳 늘고, 「움직이는 레일」이 산만해 보일 위험 | 위젯이 공용이라 **세 페이지에 함께 간다** — `schedule` 의 1개짜리 레일도 같이 움직인다 | 중간(JS 로직) |
| **C. 레일이 바탕을 갖는다** | 레일에 반투명 바탕 + `backdrop-filter`, 겹치는 구간만 `pointer-events` 조정 | **획이 글자에 안 겹쳐 보인다.** 변경이 가장 작고 본문·레이아웃 무변경. 단 «글자가 아이콘 뒤로 숨는» 모양이 되고, 클릭 문제는 별도 처리 필요 | 세 페이지 공통 | 싸다 |

★어느 쪽이든 **히어로 워드마크(§6-4)** 는 본문 규칙 밖이라 따로 봐야 한다.
★`momentedit-design` 「여백」 절: 섹션 **세로** 간격은 `.divider` 가 단독으로 정하고
  손잡이는 `--gap` 과 `+32px` 둘뿐이다. **가로 여백은 다른 손잡이**이니 혼동하지 말 것.

## 8. 이미 폐기된 발견 — «오탐»으로 기록한다

**다시 올리지 말 것.**

| 발견 | 왜 오탐이었나 |
|---|---|
| 히어로 로고 대비 `1.09:1` | **페이드인 중간**을 쟀다. 실제로는 진사 배경에 크림 글자로 정상이다 |
| `index.html` 빈 화면 연속 | **리빌 대기 1.2초**로 짧았다. 31개 화면 전부 내용이 있고 **빈 화면 0개** |

같은 세션에서 코드 쪽이 낸 오탐도 함께 적어 둔다 — 한쪽만 실수하는 게 아니다:
청첩장 「24」 대비 `1:1`(실제로는 금색 원 안의 날짜) · 레일 아이콘 라벨 없음(6개 전부 있음) ·
옛 `--light` 대비 실패(실제 4.74:1 통과) · 하단 지도 빈 박스(구글 지도 iframe · 오프라인 탓).
