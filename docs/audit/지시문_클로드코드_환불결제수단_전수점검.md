# [지시문] 환불 계좌 입력 UI × 결제수단 정합성 — 독립 재검증 및 조사 (구현 금지 · 조사 단계)

너는 momentedit-site 레포에서 아래 문제를 **독립적으로 재검증·확장 조사**한다. 다른 세션(Cowork)이 1차 감사를 마쳤고, 그 결과가 `AUDIT_환불계좌_결제수단_전수점검.md`(첨부/전달됨)에 있다. 너의 임무는 그 결론을 믿지 말고 **코드로 직접 반박 시도**한 뒤, 놓친 것을 찾는 것이다. 이번 턴에서는 **코드를 수정하지 않는다** (조사 보고만).

## 배경 요약

- 증상: 관리자 강제이동으로 '취소'된 고객의 마이페이지(mypage.html)에 환불 계좌 입력 카드(REFUND)가 노출됨.
- 질문: 카드결제 수령분이면 이 계좌 입력이 숨겨지는가? → 1차 감사 결론: **숨겨지지 않는다(수단 분기 자체가 없음)**. 현재는 PAY_CARD_ENABLED=OFF라 실사고 없음. 카드 오픈 시 문제화.

## 작업 규칙 (필수)

1. `CLAUDE.md`를 먼저 읽고 전 규칙 준수(main 직접 push 금지 · 이번 턴은 어차피 수정 금지).
2. 조사 시작 전 `git fetch origin main` 후 최신 main 기준으로 본다.
3. 모든 주장에는 `파일경로:줄번호` 근거를 붙인다. 근거 없는 주장은 쓰지 않는다.
4. 1차 감사와 결론이 다르면 "반박" 섹션에 따로 모은다(같으면 CONFIRMED로만 표기, 장황한 재설명 금지).

## 조사 섹션 (각각 별도로 수행하고 섹션별로 보고)

### S1. 수납 경로 전수 재검증
- 돈이 들어오는 모든 경로를 다시 센다: 상담 예약금(schedule/submitSchedule), 계좌이체 마일스톤(입금신호→관리자확인), 카드(98_pay_card.gs), 그 외 누락 경로가 있는지(예: 변경 수수료 `_changeFeeQuote`의 수납 경로, 추가 시착비, 스탠딩 추가요금 — **이들이 환불 산정·계좌 UI에 어떻게 잡히는지가 1차 감사의 공백이다. 중점 조사**).
- 각 경로별 기록 컬럼·동의기록 키·카드 마커 유무를 표로.

### S2. 환불 계좌 수집 화면 전수 재검증
- mypage.html `CANCEL_PANEL` / `renderRefundBank` / cancel.html / 그 외(grep: 환불계좌·refundAcct·acct 전수). guide.html·form.html·inquiry.html에도 유사 UI가 없는지 확인.
- 각 화면의 노출 게이트에 결제수단 분기가 있는지 없는지 확정.

### S3. 환불 산정·기준일
- `_refundQuote`(70_journey.gs) · `buildRefundBankState`(60_mypage.gs) · admin.gs 환불송금 큐의 기준일이 경로별로 일치하는지(취소일시 유무별). 강제이동→취소 시 취소일시가 안 찍히는 것 재현 추적(adminForceStage → _clearForwardData → ti<0 no-op).
- 혼합 수납(이체+카드) 시 환불액을 수단별로 분리할 수 있는 데이터가 현재 존재하는지(동의기록.결제수단 + 카드결제로그 시트의 금액으로 역산 가능한지) 판정.

### S4. 관리자 화면·큐
- 라이브 admin.html에서 `raw.결제수단`을 쓰는 곳이 정말 0곳인지, 환불송금 큐·상세 카드 문구 전수. 구 GAS Admin.html(운영종료)과의 기능 차분 목록.
- 취소/노쇼/미계약 × 환불계좌 유무 × 환불완료 유무 = 8케이스에서 큐 노출 여부를 표로(1차 감사 주장: 취소+계좌없음이 유일한 구멍).

### S5. 알림·고지
- 95_notify.gs NOTIFY_EVENTS 전수: 취소·환불 관련 고객 알림 부재 확인. SEND_CANCEL_MAIL 기본값. 알림톡 템플릿(TODO_알림톡_전환.md 포함)에 환불 계좌 요청용이 준비돼 있는지.

### S6. 계약서·문구·KB
- contract/v1-1.html·snap-v1-0.html의 환급 방식 조항 전문 인용. 전자상거래법 §18과의 정합은 "검토 필요"로만 표시(법적 판단 금지).
- 고객 노출 환불 문구 전수(grep: 송금·환불해 드려·계좌로) → 카드 도입 시 수정 대상 목록화.

### S7. 테스트·회귀 안전망
- automation/tests 전수: 환불 관련 커버리지 갭 목록. merge-guard.sh에 이 영역 마커가 있는지. 새 마커가 필요한 지점 제안.

## 보고 형식 (이 순서 그대로)

1. **반박/정정** — 1차 감사와 다른 결론 (없으면 "없음")

4. **케이스 매트릭스 최종본** — S4의 8케이스 포함해 갱신
