- 기준 커밋: main `cd6575d` (2026-07-25)
- 발단: 관리자 강제이동으로 '취소'된 고객의 마이페이지에 환불 계좌 입력 카드가 노출됨. "카드결제면 이 계좌 입력이 안 나오게 되어 있는가?"

## 섹션 C · 환불 산정 로직 (`_refundQuote`, 70_journey.gs 748~813)

- 계약서 v1-1 §7(청약철회·무상취소)·§9(위약금)·§4⑧(시착 공제) 단일 구현. **금액만 계산, 수단 개념 없음.**
- C1 기수령액(paid)은 상태='확인' 기준 합산 → 카드·이체 구분 없이 한 덩어리. 혼합 결제(예약금 이체 10만 + 계약금 카드) 시 "카드로 취소할 몫 / 통장으로 보낼 몫" 분리 불가.
- C2 기준일: 고객 카드·관리자 큐 모두 '취소일시' 기준 고정 의도(60_mypage.gs 69~71, admin.gs 512~516). 그러나 **강제이동 취소는 취소일시가 안 찍혀**(섹션 E) 오늘 기준으로 흘러가고, 위약 구간(D-149/59/29/9/당일)이 넘어갈 때마다 표시액이 변한다.
- C3 (문구) 위약금 구간(§9)에서는 시착비가 위약금에 흡수돼 별도 공제되지 않는데(fitDeduct 표시용), 프론트는 fitCount>0이면 무조건 "(시착 N벌 공제 반영)" 표기(mypage 2430) → 구간에 따라 부정확.
- C4 웨딩스냅은 `_refundQuote`=null → 카드에 "환불 금액은 확인 후 안내드려요"로 폴백. 정상 동작이나 스냅 위약 구조는 수동 계산 전제.

## 섹션 D · 관리자 화면·처리할 일 큐

- **D1 라이브 admin.html에 카드 인지 0.** admin.gs `adminDetail`이 `raw.결제수단`을 내려주지만(953) admin.html은 어디에도 렌더하지 않는다(grep '결제수단'·'카드 결제분' 0건). 환불송금 상세 문구는 "이 계좌로 보낸 뒤 아래 버튼으로 완료 처리해 주세요"(1387) → **카드분까지 통장 송금 유도**.
- D2 카드 뱃지 + "카드 결제분 환불·취소는 계좌 환불이 아니라 토스 결제취소로 처리하세요" 경고는 **운영 종료된 구 GAS Admin.html에만** 존재(690~703). 라이브로 이관 누락.
- **D3 취소 단계 환불 리마인드 구멍.** 환불송금 큐(admin.gs 508~528)는 stage='취소'일 때 `환불계좌`가 입력된 건만 노출. 계좌 없이도 뜨는 안전망(529~552)은 **노쇼·미계약만** 커버. → 관리자 강제취소 + 고객이 마이페이지에 계좌 미입력이면 **환불 미처리 리마인드가 어디에도 없음**.
- D4 현금영수증취소 큐(498~506): 종료 고객 기발행 영수증 정리·재발행 흐름 존재. 카드분은 애초 발행이 안 되므로 무관 — 정합 OK.
- D5 환불 완료 처리(adminMarkRefunded, 1900~1911): 동의기록.환불완료 기록 → 큐·고객 카드 동시 소멸. 멱등 OK. 단 수단 구분 없는 단일 완료 플래그라 "카드취소는 했는데 이체분 송금은 안 함" 같은 부분 완료 상태를 표현 못 함.

## 섹션 E · 상태 전이·강제이동

- E1 `adminForceStage`(admin.gs 1759~1798): 타깃 '취소'는 flow에 없어(`ti<0`) `_clearForwardData` no-op + **상담예약 시트 불변** → Bookings 상태·취소일시 그대로. 결과: ①취소일시 없음(C2 유발) ②캘린더 이벤트 잔존 가능(취소 경로별 상이) ③고객 화면은 isException이 카드 전부를 숨겨 표시 문제는 없음.
- E2 반면 상담카드의 '취소' 버튼(doAdminCancel→actCancel, consultation-booking.gs 417~439)은 캘린더 삭제 + 취소일시 기록 + setCustomerStage까지 일괄 — **같은 '취소'인데 경로마다 데이터 정합이 다름.**
- E3 ROLLBACK_KEEP_PAID(1708~1713)·PAY_ROLLBACK_GUARD(98_pay_card 160~172): 확인 수납 보존 + 카드 흔적 재청구 차단 — 최근 보강돼 정상.
- E4 예외→정상 복구 시 환불완료 흔적 제거(1729~1730) 정상.
