# 지시서 — 「파트너사」 → 「(검증한) 인근 식당」 표현 정정 (2026-09-11)

## 왜 고치나 (대표 확인 사항)

대표 확인: **다이닝 식당들과 맺은 제휴·계약이 없다.** 「인기 있고 적절한 곳으로 리스트를 뽑은 것」이다.
그런데 사이트·AI·계약서가 그 식당들을 **「파트너사」**로 부르고 있다. 두 가지가 문제다.

1. 고객이 **제휴 할인·우선 예약·품질 보증이 있는 줄 안다.** 없으면 실망한다
2. 식당 입장에서 **모르는 사이에 「파트너사」로 게시**되어 있다

★**사실에 맞는 말이 더 세다.** 우리가 실제로 하는 것은 «검증»이다 — 반경 7km 스윕 수집
(`collectDinePool`), 카카오 지도 전수 대조(`auditDineDb`), **매달 자동 폐업·상호변경 점검**
(`awMonthlyAudit`). 제휴보다 이쪽이 어렵고, 이쪽이 참이다.

## 치환 규칙

| 종전 | 새 표현 |
|---|---|
| 파트너사에 직접 지불/결제 | **식당에 직접 지불/결제** |
| 인근 파트너는 1인 2.5~4만 | **인근 식당은 1인 2.5~4만** |
| 검증된 파트너(를 제안/추천) | **저희가 검증한 인근 식당** |
| 다이닝 파트너 | **인근 식당** |
| 파트너마다 / 파트너별 | **식당마다 / 식당별** |

★**기계 치환 금지.** 문장마다 조사와 호흡이 다르다. 한 줄씩 읽고 고친다.
★**「제휴」·「협약」·「가맹」으로 바꾸지 않는다.** 그것도 없는 관계다.

## ★★건드리지 말 것

- **`contract/archive/v1-2 ~ v1-7.html`** — **절대 수정 금지.** 이미 지나간 판의 보관본이다.
  과거 계약 문서를 소급해 고치는 일은 하지 않는다.
- **`contract/v1-1.html` (현행 계약서, 2곳)** — **이 지시서 범위 밖.** 별도 판단이 필요하다.
  제337행이 **책임 소재 조항**(식중독·예약 이행 책임 귀속)이라 낱말 하나가 법적 의미를 갖는다.
  ▸계약서는 CLAUDE.md 「되돌리기 비싼 변경」이라 **병합 전 리뷰 대상**이다. 따로 올린다.

## ★함정 — merge-guard 가 막는다

`automation/tests/merge-guard.sh` **3921행**:
```
chk '다이닝 식사비는 파트너사 직접 결제' index.html 2
```
**index.html 에서 이 문자열을 바꾸면 가드가 0건으로 떨어져 푸시가 막힌다.**
같은 커밋에서 가드 문자열도 함께 바꾼다:
```
chk '다이닝 식사비는 식당 직접 결제' index.html 2
```
★가드의 의도(=「다이닝은 견적에 포함이 아니다」)는 그대로다. 감시 문구만 새 표현으로 옮긴다.
 위 3917행 주석의 「파트너사 직결제」도 같이 손봐 두면 다음 사람이 헷갈리지 않는다.

## CI 확인

`scripts/ai-live-sim-ci.js` **239행** — `['파트너|별도']` 를 기대한다.
새 문안에 「별도」가 남으면 통과하지만, **「별도」를 지우는 문장이 있으면 깨진다.**
고친 뒤 반드시 돌려 보고, 필요하면 기대값을 `['식당|별도']` 로 바꾼다.
